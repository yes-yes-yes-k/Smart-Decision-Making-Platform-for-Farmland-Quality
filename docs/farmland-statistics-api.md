# 耕地统计接口设计与口径

## 已确定口径

- 统计范围支持行政区域和当前地图视窗。行政区域已支持县、镇、村；地图缩放或平移后，前端在 `moveend` 事件调用视窗统计即可联动更新。
- 地块与范围只要实际相交即纳入“地块数”，面积按裁剪到范围内的部分计算，避免跨行政边界或视窗边缘的面积被重复计入。
- 平均值按裁剪后的地块面积加权。接口同时返回有效指标面积/数量和未分类面积/数量，缺失值或非正值不会悄悄进入最低档。
- 柱状图和饼图共用 `distribution`，柱状图使用 `parcelCount`，饼图可按 `areaMu` 或 `parcelCount` 展示。
- 所有最高档不设上限。有机质大于 40、有效磷大于 40 均继续使用各自“高”档颜色，不新增颜色。
- 有效土层厚度对接现有数据字段 `topsoil_thickness`；接口对外名称为 `effective_soil_depth`。
- 73 个村间争议面以 `zone` 保存并标记为不可选择，不强行归入任何普通村。

## 接口

所有接口使用现有 JWT 鉴权，统一前缀：`/api/v1/farmland-statistics`。

### `GET /metrics`

返回 8 个指标的名称、单位、精度、分档边界和颜色。前端图例应直接使用此接口，避免重复维护分档。

### `GET /regions`

按层级获取区域列表。查询镇列表：

```text
GET /regions?parent_type=county&parent_id=440281
```

查询某镇下的村：

```text
GET /regions?parent_type=township&parent_id=440281001
```

默认不返回争议区。仅管理或核查界面需要时可加 `include_disputes=true`。

### `POST /aggregate`

按行政区域统计：

```json
{
  "scope": {
    "type": "administrative_region",
    "region_type": "village",
    "region_id": "440281001208"
  },
  "metrics": "all"
}
```

按当前地图视窗统计：

```json
{
  "scope": {
    "type": "viewport",
    "bbox": [113.0, 24.0, 114.0, 25.0]
  },
  "metrics": ["soil_ph", "organic_matter", "available_phosphorus"]
}
```

每个指标返回：

- `table`：面积加权平均值、总面积（亩）、地块数、有效数据面积/数量、最小最大范围；
- `distribution`：按等级排序的数量、面积、数量占比、面积占比、区间和颜色；
- `unclassified`：缺失、无法解析或不在有效正值范围内的数据。

视窗联动建议由前端做 300–500 ms 防抖，并取消已经过期的请求；后端每次都按请求范围重新空间裁剪。

### `GET /parcels/{parcel_id}`

返回地块编号、区域编码、耕地质量等级、有机质、pH 和有效磷。

### `POST /parcels/pick`

用于地图点击后的点选查询：

```json
{
  "longitude": 113.35,
  "latitude": 25.13
}
```

若重叠地块同时命中，返回面积最小的地块；未命中返回 404。

## 当前数据结论与后续替换点

- 当前 5488 个地块不是单一县数据，而是分布在韶关多个县区并少量延伸到英德；此前 `area_code` 全部硬编码为新丰县 `440233`。
- 已按广东县界做空间审计，自动纠正仅限主导县覆盖比例不低于 95% 的地块。低置信地块保留原值并进入人工复核清单。
- 当前地块指标来自测试数据，接口可用于开发联调，但生产展示前仍需确认正式地块和指标数据源。
- 当前乐昌边界已切换登记为土壤所提供的广东 L2/L3/L4 数据源。该数据的几何沿袭信息指向 2016 年、导出元数据为 2020 年；它与此前乐昌独立边界逐要素完全相同。拿到真正更新的权威边界后，应沿用同一导入和差异审计流程替换。
