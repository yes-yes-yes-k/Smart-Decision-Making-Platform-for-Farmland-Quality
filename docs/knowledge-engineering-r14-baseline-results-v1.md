## 两类漏失及成因

**1. 排名漏失（17 条）**：引用块存在于库中，但没有进入前 20。U3 的文献排第 2，返回的却是该文档第 1/0/5 块，引证所在 104—106 块全部缺失；U5 文献排第 1，返回 17 个该文档块，引证所在的 59/98/100 块均不在内。说明 **文献级排序已可用，块级排序仍按语义相似度而非"能否回答子问题"**，这是 R1.2c 独立文献排序没有覆盖的部分。

**2. 无法定位（7 条）**：R2.1 对 5 篇问题 PDF 重新解析（449、104、1149、1141、308），`legacy_mapping` 只到页码级（`same_page_only_no_span_transfer`），旧引用在新文本中逐字不存在。示例：U3 的引文 `microbial activity led to the accumulation of C in the grass plots...` 在 104 的新解析 147 个块中既无精确匹配也无空白归一匹配。**这意味着 R2.1 的"新旧来源位置映射"只完成了页面级，跨度转移没有交付**，R1.4 的证据级验收因此对这批文档无从判定。

## 顺带修掉的环境缺陷

首轮运行全部 503：Chroma 报 `error returned from database: (code: 14) unable to open database file`，向量路静默降级为纯词法，`retrieval.mode` 变 `degraded`。原因是沙箱把 `%TEMP%` 设为不可写，而 Chroma 的 Rust SQLite 层不使用 Python 的临时目录回退。脚本现在在启动前显式钉住 `TMPDIR/TEMP/TMP` 到运行目录下的 `.tmp`，修复后 9 个用例全部 `hybrid`、无降级。

该缺陷会静默影响任何"混合检索"结论：**只看接口 200 和返回条数无法发现降级**，必须读 `retrieval.mode`。建议在监控里把 `mode != hybrid` 作为告警项。

## 限制

1. 语义支持未评估：排名只证明位置，不证明原文支持该结论；`support_verified` 仍为 false。
2. 四个变体没有子问题，只做文档级判定。
3. 未生成答案、未新增嵌入请求、未写生产库或索引。
4. 重解析文档的证据定位在跨度转移完成前不可用；本批不据此判定这些文档的检索质量。
