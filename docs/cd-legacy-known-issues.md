# Cd 迁移：原系统已知问题清单（迁移期保持一致的记录）

> 用途：迁移期一律**与原系统逻辑一致**，下列问题不擅自修正，统一记录在此，待迁移收口后讨论。
> 记录日期：2026-11-07。每条给出：原系统行为 → 当前实现（一致） → 影响 → 待讨论点。

## 1. 净通量分布三档重叠

- 原系统 `_calculate_distribution`：负值 `v<0`、接近平衡 `-5≤v≤5`、正值 `v>0` 三档互相重叠。
- 当前实现：沿用该定义（`mutually_exclusive: false`），占比一律 `round(...,2)`、不补差。
- 影响：同一条记录可同时计入两档，三档占比之和可能超过 100%（示例数据 150.01%）。
- 待讨论：是否改为互斥三档（`v<-5 / -5~5 / v>5`）并使占比和恰为 100%。

## 2. 未来情景预测：区域参数不参与查询

- 原系统 `predict_future_cd`：`area` 只进日志，源码标注 TODO，实际查询全量。
- 当前实现：一致——区域参数仅记录在响应（`area_filter: not_applied`），查询全量。
- 影响：按区域请求预测会拿到全域结果。
- 待讨论：是否让区域过滤真实生效（复用阶段 3 归属依据）。

## 3. 移除计算：区域参数不参与查询

- 原系统 `calculate_grain_removal_by_area` / `calculate_straw_removal_by_area`：`area` 仅用于地图边界。
- 当前实现：一致——计算按全量执行、区域参数仅记录；**统计/点位/导出**仍按区域过滤（对应原系统按乡镇空间过滤的统计入口）。
- 影响：按区域执行移除计算会写回全域的移除项。
- 待讨论：计算侧是否也按区域过滤。

## 4. 未来预测统计口径（样本标准差 / 线性插值分位）

- 原系统：`pandas.DataFrame.std()`（ddof=1，样本标准差）、`quantile()`（线性插值）。
- 当前实现：一致——返回 `count/mean/std(ddof=1)/min/max/median/percentile_25/percentile_75`。
- 影响：与阶段 2 已确立的**总体标准差 + 下标直取分位数**口径不同，跨模块对比需换算。
- 待讨论：统一为阶段 2 口径，还是保留原系统口径。

## 5. 秸秆移除：分母非正的样点静默跳过

- 原系统：`exp(ln)×0.76−0.0034 ≤ 0` 时跳过该样点，仅写日志。
- 当前实现：一致——跳过；响应含 `skipped_invalid_denominator` 计数仅为可观测性（不影响数值）。
- 影响：极低浓度样点没有秸秆移除值，汇总时容易被忽略。
- 待讨论：是否在对外口径中显式声明跳过样点。

## 6. 通量公式：两种模式两套口径

- 原系统：CSV 模式用常量（0.023/0.368/0/0）与固定 2000 kg/ha；数据库模式从输入表读实际值并乘 `bd020_90`。
- 当前实现：采用**数据库模式**（原系统在线主链路），未实现 CSV 模式的常量口径。
- 影响：与原系统 CSV 离线模式的结果不可直接对比。
- 待讨论：是否需要复刻 CSV 模式作为对照。

## 7. 可视化边界：只取第一个要素

- 原系统 `create_raster_map`：`json.loads(gdf.to_json())["features"][0]["geometry"]` 只取第一个要素。
- 当前实现：按 `region_id` 查询单个区域几何，行为一致；若未来支持"整县多乡镇同图"需再评估。
- 影响：多要素边界场景（整县出图）会只画第一块。
- 待讨论：是否需要多要素支持。

## 8. 当年浓度阈值：统一 0.3 / 0.6 mg/kg

- 原系统：统一阈值；GB 15618-2018 实际按 pH 分档（≤5.5 / 5.5–6.5 / 6.5–7.5 用 0.3，>7.5 用 0.6；管制值另计）。
- 当前实现：一致——统一 0.3 / 0.6。
- 影响：酸性土壤（本库 53.8% 的 pH≤5.5）用 0.6 作"超标"线偏松。
- 待讨论：是否按 pH 分档或改用"筛选值/管制值"双档。

## 9. 容重缺失回退 1.0

- 原系统：`bd020_90` 缺失回退 1.0。
- 当前实现：一致——回退 1.0 并返回回退计数。
- 影响：耕地实际容重多在 1.1–1.5，回退 1.0 会使当年浓度偏高约 20–30%。
- 待讨论：是否导入第三次土壤普查容重数据（`third_survey_bulk_densities` 目前 0 行）。

## 10. 插值失败保留原栅格

- 原系统 `interpolate_nan_values`：异常时返回未插值栅格（保留 NaN），仅日志。
- 当前实现：一致——不降级、不中断。
- 影响：点位稀疏区域开启插值后可能出现整片空白。
- 待讨论：是否需要降级策略。

## 11. 阶段 7 土重口径与 v2 `end_cd` 的差异（2026-11-14 引入）

- 原系统：`Future_Cd = (Initial + Net×years) / (2000 × bd020_90)`，耕层厚度固定 0.2m，不读深度。
- 当前实现：**严格照抄**——分母 `2000 × bulk_density_g_cm3`，不读 `soil_depth_m`。
- 影响：v2 `calculate` 的 `end_cd` 走 `soil_depth_m × bulk_density × 1e7` 推导，两者仅在 `soil_depth_m = 0.2` 时数值等价；其他深度下未来预测与当年浓度会有系统性差异（0.15m 差 1.33 倍、0.3m 差 0.67 倍）。
- 待讨论：是否改为按 `soil_depth_m` 推导（更物理，但与历史结果不可比）。

## 12. 阶段 6 写回必须显式年度（2026-11-14 引入）

- 原因：v2 唯一键为 `(source, parcel_id, sample_id, accounting_year)`，而作物 Cd 结果表 `cd_cd_prediction_result` 没有年度字段，无法自动推导归属年度。
- 当前实现：`write_back=true` 时缺 `accounting_year` 直接拒绝（`year_required`），不猜测、不写全年度。
- 影响：调用方必须知道数据属于哪个核算年度；批处理需按年度分批执行。
- 待讨论：是否在作物结果表补年度维度，或建「地块—年度」对照表。

## 13. 阶段 6 写回只覆盖指定年度，其余年度与来源保持原样（2026-11-14 引入）

- 当前实现：按 `select_inputs` 返回的 `id` 精确更新，只改两列并递增 `input_revision`；legacy 行与多来源歧义样点不写回，只计数披露。
- 影响：同一地块多年度数据里，只有被请求的年度更新，其余年度保留旧值（这是 v2 年度维度的预期语义，不是缺陷）。
- 待讨论：是否需要「跨年度批量重算」的编排入口。
