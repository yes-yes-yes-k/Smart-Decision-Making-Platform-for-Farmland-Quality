# v4-r3 标注流程校准结果

2026-10-27。按试标澄清清单实施新修订，并对同一10个开发校准样本运行两组AI试标。结论：技术通过情况改善，但仍未通过技术、一致性和语义门槛，剩余90条未启动。

## 已落地的校准

- 历史v4.0/r2手册、校验器、原始响应不变，新模块为 `evaluation_v4_r3.py`。
- 可读A类即使没有关系也必须可评；禁止用关闭eligibility隐藏负例或漏标。
- 重复事实要求合并证据；肯定关系不能仅靠题名，不能与relation_eligible=false并存。
- 对澄清清单中的明确反例增加检查：土壤肥沃不是具体可测指标；沸水提取、PCR、分光光度法不是田间措施。这是反例保护，不是完整的领域语义验证器。
- 只对空白差异做有记录的原文对齐，不修字母、大小写、标点或OCR字形；原始请求片段和最终原文跨度同时保留。r3有效配对结果中的绑定均为exact，不能声称本次改善来自空白对齐。
- 实体/质量标注与关系判断分开，关系从合法类型方向候选中选择；合法方向不代表事实成立。
- 调用前冻结10条门槛、代码与规则哈希，每阶段最多一次修复、请求时限60秒。A/B请求独立，均不提供旧标签或另一份答案；同一提供者仍有相关偏差。
- `--expand` 检查技术、一致性、逐条语义复核及配置哈希，未通过时在创建请求前拒绝。

## 实际试标结果

| 指标 | r2历史试标 | r3 |
|---|---:|---:|
| A组完整通过 | 2/10 | 5/10 |
| B组完整通过 | 5/10 | 7/10 |
| 两组共同完整通过 | 2/10 | 5/10 |

本次5条配对样本的实体一致性F1为44.44%，正例关系两组均无可比较项，因此关系F1为未定义，不当作100%一致或通过。不能将上述少量配对结果当作全库准确率。

失败分解：A组4次规范化状态与值冲突、1次非原文片段；B组1次A质量却关闭可评任务、2次非原文片段。没有最终网络失败，也没有关系方向错误，但后者部分因为模型没有成功产生可比较关系，不能据此证明关系判定能力改善。

本轮已报告71,095 token，实际费用未知；所有试标进程已结束。

## 原文语义复核

Codex复核全部10条输入及两组结果，4条仍有明确的未解决关键语义问题：

1. SOC、CC、fPOM明确存在的原文，两组都给空集——共同漏标不能因“一致”而被接受。
2. 天气服务文档中，把高标准农田、气象服务、气象灾害和人工影响天气标成标准。
3. 一组漏掉正文明确的GB标准编号。
4. 将“已修复的土壤”和生物可利用重金属裸概念当作当前障碍，另一组全空。

其他案例保留规范化、OCR引用、题名概念范围及质量判断待定。没有把它们自动裁决为新金标。逐条输入哈希及复核理由见 `artifacts/knowledge_platform/gold-v4/calibration/r3/source-review.json`。

## 门槛与后续

技术要求两组10/10有效；实体一致性F1≥0.90、正例关系F1≥0.85且不能靠空集抬高；10条全部原文复核、关键问题为0。目前三项均未通过。扩量命令已实际验证被 `pilot_gate_not_passed_for_this_config` 拦住，没有发送剩余90条，也未恢复抽取后端实验。

36项相关测试通过，包含新校准规则、评分器和既有回归。扩量前最需要的是验证/调整AI标注者的本体理解与穷尽性能力，且应先在独立短控制样例上证明有效；继续改格式或单纯加提示词不能消除共同漏标。当前只确认实现了校准机制，没有确认当前标注者已合格。
