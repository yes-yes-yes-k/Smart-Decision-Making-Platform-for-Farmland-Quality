# R1.4 意图拆解离线探针（词法链路）

日期：2026-10-31。目标：在不新增模型调用的前提下，判断"把一个问题拆成多个意图"能否把 R1.4 漏掉的证据找回到 60 候选内，再决定是否上调预算。

## 方法

`scripts/probe_intent_decomposition_offline.py`，只用生产词法索引（`enterprise_kb`，107,505 块），不碰向量、不调模型：

- **基线**：原问题直接做词法检索，取前 200；
- **变体**：①`concept_and`（问题概念组 AND）②`measure_indicator`（仅措施+指标概念）③`indicator_only` ④`keyword_or`（分词后 OR）；
- **合并**：各变体结果按 (document_id, chunk_index) 取最小排名组成并集；
- **目标**：24 条参考证据，经跨度转移映射到当前块（15 个不同块）。

## 结果

| 指标 | 数值 |
| --- | ---: |
| 参考证据 | 24 条（15 个不同块） |
| 原查询词法前 60 命中 | 2 条 |
| 原查询词法前 200 可达 | 3 条 |
| 拆解后进入前 60 | **7 条**（+250%） |
| 变体预算放到 200 后可达 | 8 条 |
| 任何变体、任何深度都没出现 | **16 条** |

拆解确实有效，但很快到顶：

- 命中排名分布：第 3、13、16、47、53 名，其余仍未进入；
- 变体贡献：`measure_indicator` 3 条、`concept_and` 2 条、`keyword_or` 2 条、`indicator_only` 0 条；
- 按用例：U1 捞回 4 条、U5 2 条、U3 1 条；**U2、U4 一条都没捞回**；
- 把变体预算从 60 抬到 200，只多捞回 1 条——说明剩下的不是"排得靠后"，而是**词法索引里根本排不上来**。

## 结论

1. **意图拆解值得做**：零成本把词法前 60 的覆盖从 2 条提到 7 条，且不需要改索引或模型。
2. **但它不足以回答"60 候选够不够"**：16 条证据在词法链路上无论多深都取不到，占三分之二。是否上调候选预算，取决于**向量链路**能否召回它们，而词法探针给不出答案。
3. **上调预算现在没有依据**：如果证据压根不在词法结果里，扩大预算只会增加无关候选和延迟，不会提高命中。

## 需要的最小授权

要验证向量侧，只有一条路：为 12 个子问题各生成一次查询向量（现有 9 条冻结向量只对应原问题，无法替代）。

| 项 | 估算 |
| --- | --- |
| 请求数 | 12 次嵌入（可选再加 5 条条件变体，共 17 次） |
| 输入 token | 12 条子问题合计 153 字，约 **100 token** |
| 输出 | 无（嵌入模型不计生成） |
| 用途 | 每个子问题单独做向量召回，与现有词法并集合并，测 60 候选覆盖率 |

这是目前最小、最省的一次授权请求；R1 的独立额度已耗尽，不能自动沿用。

## 限制

- **只有词法半边**：向量侧未拆解，结论只能说明"词法可达性上限"，不是端到端召回结论。
- **排名不可跨变体直接比较**：合并时按最小名次近似，只用于判断"是否可达"。
- **目标块经跨度转移**：5 条部分定位的块可能不是原文精确位置，可能低估命中。
- **词法上限 200**：索引接口单次最多返回 200 条，更深的排名不可测。

## 建议

先申请上述 12 次嵌入（约 100 token），跑一次"子问题级向量召回 + 词法并集"的可达性测量：

- 若 60 候选能覆盖大部分目标 → 不上调预算，改为在检索端做意图拆解；
- 若仍大量缺失 → 再讨论候选预算或索引粒度，并单独计量成本。

两条路都不改动生产默认配置。
