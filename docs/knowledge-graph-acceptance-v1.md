## 数据隔离与局限

本地只读核查数据库及公开已审核分块，不写生产图谱、数据库或向量索引。隔离按文件哈希、DOI、标准号去版本、同题名身份关联形成文档组；已知曝光会传播到整个关联组。高度相似的文档对隔离待查，未被直接认定独立。

已从53,808条可用分块快照中确定性抽出500块。按来源类型、语言、解析质量及位置选择；缺失元数据记unknown。代表性样本不筛掉难块或OCR问题，但当前每组需至少3块，短文档未进入代表性轨，这是明确的抽样限制，不能据此宣称全库概率代表性。

选中样本之间、以及选中样本与历史1000块，另做了穷举近重复检查。该结果不证明全库语义重复为零，少于80个规范化字符的短块未做语义去重；本地曝光记录也不能证明模型训练数据未见过材料。基准只声明项目内记录范围的文档留出，不宣称严格盲测或专家认证。

代表性轨和挑战轨分别评分，不合并抬高整体分数。每种关系30个事实、10个文档组仍是待标注验证的覆盖目标，不是当前已达标结果。

## 问答与检索实现

任务包预设60道可答题，其中20道需组合多段证据；40道不可直接回答题分为资料不足20、错误前提10、超出证据10。模型生成后须通过片段绑定和独立来源复核，草稿不能自动成为参考。

不可答性明确限定为“仅依据指定文段”，不根据图谱无边推断事实不成立，也不声称整库或整篇文献没有答案。因此首版拒答指标衡量给定证据边界下的克制，不能当作全库不可回答性认证。多跳题需两块以上证据共同支持，独立复核还要检查是否真正需要组合，而非拼接无关问题。

隔离检索组件接收冻结语料的既有向量、查询向量与嵌入模型标识，使用真实余弦检索及项目的 `JsonGraphStore` 后端。向量路和GraphRAG路同样最多5块、每块最多1600字符；GraphRAG最多3块图证据，再用向量结果补齐。模型生成参数由同一配置固定。图只能从标记为候选抽取流程输出、来源哈希匹配的预测构建；不得用参考关系建图。两个分区不能混建图，GraphRAG后端缺失时不静默回退为向量路。

目前只有离线组件及测试，**尚未导出隔离的嵌入快照、尚未运行新的候选抽取建图、尚未执行真实两路问答对照**。测试中的小型向量和图是验证实现行为的夹具，不是业务测评结果。

引用必须逐字绑定到实际送入回答模型的检索上下文，引用到全库中但未提供的文字也会拒绝。关键词命中不能证明回答有据；问答评分另接收独立语义判定，并保留同模型裁判偏差声明。

## 评分、阈值和操作入口

数据目录为 `artifacts/knowledge_platform/acceptance-v1/`：

- `development-freeze.json`、`run-config.json`：原回归集与运行配置冻结。
- `pool/`：文档审计、曝光记录、隔离快照、500条选样及近重复检查。
- `calibration/`、`test/`：100条/400条来源及原文输入；尚无新参考标签。
- `stability/`：100份盲复标响应、分层比较、仲裁失败、未解决清单。
- `qa/generation-jobs.jsonl`：100份来源绑定任务，尚不是100道参考题。
- `progress.json`、`review.html`：可检查进度和原文。
- `threshold-proposal.json`：未校准的讨论占位，不是可供批准的数值建议。
- `final-acceptance-report.json`：`executed=false`、`status=inconclusive`。

现有新参考不足时，评分结果必须列出缺失参考及全部选样分母；不能只对少量有标签样本宣布通过。缺失或格式错误预测在有合格参考的任务上计漏报和完成率损失；参考排除掩码同时作用于两边。正文、题名和两条轨道分别报告。问答会分别约束有据率与可答完成率，不能靠全拒答通过。

```powershell
# 纯本地：重建报告和审核页
.venv/Scripts/python.exe scripts/report_kg_acceptance_v1.py
# 纯本地：重核选中样本与历史快照的近重复
.venv/Scripts/python.exe scripts/audit_kg_acceptance_isolation.py
# 校准评分；需要真正的预测JSONL，当前缺参考时只报告证据不足
.venv/Scripts/python.exe scripts/score_kg_acceptance_v1.py extraction --predictions <预测.jsonl> --output <报告.json>
```

抽取预测行接口为 `sample_id/input_sha256/answer`，answer仍使用v4原文片段五字段协议。参考仲裁提案包含 `visible_input/annotation/source`，其中source保留track、partition和isolation_group。问答预测包含题目id、state、answer、abstain、已验证引用及实际检索sample_id；语义判断按同一id单独提交。源哈希错误、重复或未知样本会阻止评分。

最终评分的 `--partition test` 入口要求用户确认文件与冻结协议哈希匹配。协议必须包含 `dataset_ready=true`、参考及选样哈希、实现清单哈希和显式阈值；阈值分 `extraction.representative`、`extraction.challenge`、`qa`。每项规则明确minimum或maximum之一，并设置正的minimum_support。零支持、缺指标、缺参考不能判pass；确认后的参考或实现发生变化也会阻止评分。

先完成真实校准试测，再提交具体阈值及允许错误数的影响报告，由用户确认。当前不请求批准占位数值，也不生成虚构的最终成绩。

## 当前下一步

云端继续暂停时，可使用审核页检查来源、取样和旧复标错误；现有工具不会自动消费额外调用。之后依次恢复来源仲裁与两臂标注、问答生成及独立复核、隔离嵌入与候选图快照、校准对照，最后再进入用户确认阈值步骤。仍有语义分歧或覆盖不足的任务保持未知，不强行发布。
