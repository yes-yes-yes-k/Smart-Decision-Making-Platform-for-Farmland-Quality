# 原文位置选择式抽取 v10

通过 `--profile v10-span --diagnostics` 启用实验。默认 v6 保持不变，冻结参考、验证集与测试集不变。

## 原文位置协议

程序为原文建立 token 表：英文和数字连续片段为一个 token，汉字逐字、其他非空白字符逐个记录。每个 token 有原始 Unicode 字符起止位置；空白不成为独立 token，但包含在选择区间的原文切片中。

实体阶段只能输出 `start`、`end` 和 `type`，区间左闭右开。程序根据 token 位置切出名称并记录 `span_start`、`span_end`，不接受模型自由生成名称。类型仍需模型判断，字面存在不意味着类型或语义正确。

关系阶段只能选择冻结实体 ID、关系类型和证据 token 区间。引用由原文切片生成，必须覆盖所选择的两处实体字符位置，不能用原文其他位置的同名实体替代。方向需符合 schema，引用长度不超过 800 字符。

为保持现有 GraphRAG 记录协议，跨换行或包含记录分隔符的实体区间会被拒绝，而不是静默改写名称。相同名称不同类型也会被拒绝。每阶段最多两次修复；最终失败计为整条请求失败，原始选择和阶段错误保存在诊断中。

## 交付与评测

- 实现：`framework/knowledge_graph/span_extraction.py`。
- 位置、重复实体和证据约束测试：`tests/test_kg_span_extraction.py`，连同既有回归共 32 项通过。
- 真实实验：相同冻结开发集 180 个分块，四并发，原有硅基流动模型；不发送参考答案，不写生产图谱。
- 输出：`artifacts/knowledge_platform/gold-rebuild-v3/development-span-v10/comparison.md`、`comparison.json`、逐条错误和来源验证。
- 实体位置保留于真实响应 `diagnostics` 的 `entity_span_selection.resolved` 中，可直接核验 `text[span_start:span_end] == name`。

比较沿用先前 v6/v8/v9 在相同样本上的真实结果，非随机交错实验；位置选择消除自由名称输出路径，但未预设能改善领域召回率。严格评分仍受规范名/别名、引用边界和 AI 参考标注限制，不将结构校验等同语义评测通过。

## 真实结果（2026-10-27）

180 次尝试，163 成功、17 失败。实体严格精度 9.43%、召回率 0.81%，关系预测为 0。163 份成功产物通过结构与来源校验，但抽取质量不合格，拒绝推广。失败包括跨行区间 9、越界 3、方向错误 1、不完整输出 1、连接失败 3。已报告 401,947 个 token。后续 15 个合成控制进一步显示模型混淆 token ID 与字符位置，见 model-capability-controls 原始响应；小样本控制不代表总体模型能力评估。
