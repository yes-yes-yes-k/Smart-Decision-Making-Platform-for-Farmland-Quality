# 降低思考强度的实测结论

日期：2026-10-31。问题：能否下调模型的思考强度以降低成本？**能，但只有"默认强度"能稳定产出关系**；压低后关系抽取归零。

## 三档实测（同一篇 1141，同一提示词）

| 配置 | 用量 | 耗时 | 接受 | 关系 |
| --- | ---: | ---: | --- | ---: |
| 默认（不设上限） | 21,854 | 250.4s | 1 研究 / 3 实体 | **1** |
| `thinking_budget=1024`，输出 4096 | 4,558 | 28.6s | 1 研究 / 2 实体 | 1（单篇偶然） |
| `enable_thinking=false` | 3,065 | 8.2s | 1 研究 / 2 实体 | **0** |

十篇整体在 `thinking_budget=1024` 下跑完（53,602 token、5 分 11 秒），**关系全部为 0**；`thinking_budget=4096` 复测 1141 与 1015，关系同样为 0。

## 结论

1. **参数确实有效**：`thinking_budget` 能压住推理开销，1024 时单篇从 2.2 万降到 4.6k（−79%）、耗时 −89%。
2. **但关系抽取依赖推理**：预算压到 4096 及以下时，模型只做实体罗列，不再构造"措施→指标"关系。十篇里关系为 0，等于丢掉 R2.5 的核心产物。
3. **完全关闭更差**：3,065 token、8 秒，但连关系字段都不产出。
4. **截断风险随预算下降而上升**：1024 时有 2 篇 JSON 被 4096 输出上限截断（12k、15k 字符处），需要 8k 以上输出上限。

## 建议

- **关系阶段保持默认强度**，这是目前唯一能稳定产出关系的配置。
- 若要继续压成本，只剩"两阶段"一条路：低思考做实体枚举（便宜），再对少量候选实体对用默认强度判关系。需新实验验证，预计十篇可压到 12—15 万 token。
- 不建议换非推理模型：会改变可比性，且需在 R4.1 重新登记。

## 预算影响

A 阶段（默认强度跑完剩余 8 篇，批准 22 万）目前已消耗约 **8.3 万**在强度实验上：

| 运行 | token | 说明 |
| --- | ---: | --- |
| v11 十篇 @1024 | 53,602 | 关系全 0，不可用 |
| v12 两篇 @4096 | 16,779 | 关系 0，不可用 |
| v8/v10/v7 单篇对照 | 12,637 | 强度对照 |

剩余约 **13.7 万**，而 8 篇按默认强度需约 **17.6 万**，缺口约 **4 万**。
