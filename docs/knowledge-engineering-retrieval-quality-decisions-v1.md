# 检索质量与本机运行：设计树及决策记录

日期：2026-10-30。这里只记录访谈决定、依赖与事实依据；实施顺序见[计划](knowledge-engineering-retrieval-quality-plan-v1.md)，领域用词见[术语表](../GLOSSARY.md)。

## 设计树

```text
目标：先让现有文献可被可靠检索并在本机实际使用；10k/100k延后
├─ 交付与运行
│  ├─ Q1 本机使用
│  ├─ Q6 纯后端，不涉及前端（覆盖此前的前端入口提议）
│  └─ Q7 一键启停、状态检查、持续处理、重启恢复；开机自启延后
├─ 检索质量
│  ├─ Q2 先验论文与支持段落；回答、跨论文对照分别检查
│  ├─ Q5 保留背景相关，支持程度与条件明确性分别表达
│  └─ Q10 默认论文，可显式选择标准、指南或全部合格来源
├─ 真实使用检查
│  ├─ Q3 从现有原文拟定查询，由用户确认
│  ├─ Q4 已确认五类问题
│  └─ Q9 前10文献、前5支持证据、准确定位与条件表达逐项检查
└─ 抽取修复
   └─ Q8 先原十篇，检查全文中的任务相关内容；不以固定8块算完成
```

## 用户决定

| 问题 | 已确认的决定 | 依赖与影响 |
| --- | --- | --- |
| Q1 | 先本机实际使用 | 暂不交付远程多人服务 |
| Q2 | 优先找到相关论文和真正支持问题的原文 | 速度、回答流畅度不能替代检索质量 |
| Q3 | 依据现有文献拟定问题供确认 | 不另起大规模评测集 |
| Q4 | 接受计划所列五类问题 | 文献线索只用于核对，不写死到召回规则 |
| Q5 | 主题相关但尚无直接支持仍可保留，明确状态 | 未命中不等于无证据、无影响；见ADR-0003 |
| Q6 | 本次不涉及前端 | 知识库页面改动提议撤回；交付接口与本机运行工具 |
| Q7 | 一键启动/停止、状态检查、持续处理、重启恢复 | 开机自动启动延后 |
| Q8 | 修原十篇，按任务相关正文与有效证据检查覆盖 | 处理排版交织、定位错误及六篇空输出，不全库重抽 |
| Q9 | 已知相关文献前10、可回答子问题的支持证据前5，定位及条件表达准确 | 五类逐项报告，并含少量同义、条件不符、无证据检查；不是全库质量认证 |
| Q10 | 默认论文，其他合格来源由接口显式选择 | 不扩大来源资格或可见权限 |

Q6的用户原话为“本次改动不应该涉及前端”；不能将之前发现前端目录解释为前端修改授权。Q9和Q10均已由用户回答“是”，不再列作待定偏好。

## 已核实事实与推断边界

| 事实 | 依据 | 不能据此声称 |

| M2完成112168分块隔离性能与恢复验证 | [M2结果](knowledge-engineering-m2-results.md) | 已部署、检索相关性通过或100k容量通过 |
| M1查看80/1306块，29条记录仅2条通过定位，6篇空输出 | [M1结果](knowledge-engineering-m1-results.md)、`artifacts/knowledge_platform/evidence-m1-v1/record-compilation-v1.json` | 2/29是语义准确率，或空输出证明全文没有结果 |
| 新证据搜索使用词法候选；研究条件仅校验格式 | `framework/knowledge_graph/research_retrieval.py` | 已有中英文语义召回或结构化条件匹配 |
| 原抽取协议要求原块号与唯一逐字摘录，编译器严格查找 | `framework/knowledge_graph/research_extraction.py`、`research_records.py` | 放宽字符串匹配就能证明语义支持 |
| 两个完整启动入口调用应用工厂，工厂存在启动补表/补列 | `start_http_server.py`、`start_production_server.py`、`framework/api/app.py` | 不传`--init-db`即可避免数据库变更 |
| 前端在相邻仓库，新证据接口尚无消费者 | 已完成的定向只读调查；不属于本次改动范围 | 新功能已接入用户界面 |

只读诊断进一步发现：27条拒收按首个失败字段分为17条无全篇精确子串、6条指定块内重复、4条块号错误。17条中6条去空白后可在指定块找到，11条经常见Unicode/空白/连字符诊断仍无全篇子串。统计是错误定位线索，保留旧拒收结论；不等于判定记录语义真伪。

来源449块51、1149块61可见双栏文本交织。哈希一致、重解析可复现与阅读顺序正确是不同判断，具体修复尚需回到PDF核实。

## 未定事项与处理方式

| 项目 | 当前状态 | 后续动作 |
| --- | --- | --- |
| 真实支持段落及可回答子问题 | 五个方向已确认，支持清单尚未逐项核实 | 检查原文；证据不足的项保留未决，不反向编写标签 |
| 解析、定位、融合与重排方案 | 技术候选，尚未选定并实现 | 基于实际错误验证；常规工程选择由实现证据决定 |

| 新模型批次与预算归属 | 未授权具体新调用 | 准备请求清单、预留和上限，再按既定预算约束处理 |
| 整体实施启动 | 业务范围和门槛已逐项确认，尚无新一轮开始实施指令 | 当前只执行用户要求的文档整理 |

以上工程事实不交给用户猜测；只有新增业务取舍、明确预算或授权边界需要用户决定。没有将所有未定技术项伪装成已确认架构，也没有把Q1—Q10再次变为待回答问题。

## 后续分支：抽取闭环、图谱增益与领域约束技术栈

用户随后要求核实上传到检索是否真正贯通、GraphRAG相对向量检索的收益及OpenSPG替代路线；本轮继续写文档，不启用新后端。

| 问题 | 用户决定 | 影响 |
| --- | --- | --- |
| Q11 | 首期要求领域规则校验及有据关联，暂不要求自动推导原文未报告的新科学结论 | 领域约束、语义支持和科学推理分别判断 |
| Q12 | 允许额外容器或独立服务 | Windows原生运行不是硬约束；允许评估不等于已授权安装或部署 |
| Q13 | 先验证真实链路和图关联价值，再决定新增平台 | 接受ADR-0004；先复用Python/PostgreSQL，不先切换到OpenSPG/Neo4j等平台 |

该分支依赖树为“核实实际链路与现有收益 → 明确领域约束(Q11)及部署可选范围(Q12) → 比较约束层/抽取层/图存储替代路线 → 决定引入顺序”。目标服务器的具体系统与资源尚无实测证据，本机Windows与现有部署文档不能替代目标环境事实。

现有链路及对照已核实并整理到[GraphRAG闭环及技术栈核查](knowledge-engineering-graphrag-stack-assessment-v1.md)。Q13已由用户明确确认，[ADR-0004](adr/0004-domain-constraints-with-reusable-backends.md)已接受。当前不存在待决定的Q13，后续仅在具体能力缺口出现时讨论新增平台；Q12允许服务不解释为已选定特定产品。
