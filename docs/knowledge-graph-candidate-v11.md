# 原文候选 ID 选择诊断与试验

## 小样本诊断

在 3 个短合成文本（中文正例、英文正例、会议负例）上分别使用普通 JSON、JSON object、JSON schema、token 区间和候选 ID 五种方式，共 15 次真实调用。无修复重试，原始请求和响应保存在 `artifacts/knowledge_platform/gold-rebuild-v3/model-capability-controls/`。

每种方式严格整例命中均为 1/3。该数值高度依赖名称边界与仅 3 个样例，不是模型能力的统计估计。具体异常比总分更有用：英文 token 模式返回字符数值而非 token ID；中文模式选择到 `pH。` 而非目标名；候选列表若包含原文没有的词，模型仍可能选择它们。普通输出也有遗漏，不能把所有问题归因于结构化输出接口。服务返回的模型名称与请求一致，但这不能独立验证服务内部路由。控制调用已报告 1,640 个 token。

## v11 实现与边界

`framework/knowledge_graph/candidate_selection.py` 从固定手写词表和标准编号模式匹配原文候选；未使用评测参考标签生成词表。每个候选有本地确定的名称、类型建议、字符跨度和 ID，最长同类型重叠名称优先保留。模型只接受候选 ID，拒绝越界、非整数或生成名称；字面匹配并不保证类型正确。

实体选择后，程序按合法方向生成候选关系并计算覆盖两处实体的最短句子窗口，引用不超过 800 字符；模型仅选择候选关系 ID。既有严格 schema 校验和最多两次修复保留。该方案受固定词表覆盖上限制约，不是通用 NER 后端；不把模型选中率冒充全库召回率。

诊断性试验冻结 24 个开发分块（关系、实体、负样本各 8），预设仅当实体 F1 和关系 F1 都超过相同样本的 v6 才考虑扩大。评分器单独报告候选对参考实体的严格覆盖上限。验证集和测试集继续隔离，生产默认仍为 v6。

36 项相关测试通过。原始响应、逐条误差和报告保存在 `artifacts/knowledge_platform/gold-rebuild-v3/development-candidate-v11-pilot/`，不能从结构与来源校验通过推断语义质量通过。

## 本轮结果与决策

24/24 成功，0 失败，实体精度 58.33%、召回 9.33%、F1 16.09%；相同样本 v6 为精度 100%、召回 29.33%、F1 45.36%。v11 关系预测为 0。8 个负样本均正确。已报告 6,065 个 token，加上合成控制 1,640，本轮共 7,705 个；实际费用未知。

实体参考共有 75 个，候选词表只严格覆盖 23 个（30.67% 上限），模型最终保留其中 7 个。18 条参考关系中，候选池严格覆盖仅 2 条；实体筛选后可用关系降至 0，关系阶段实际调用为 0。因此本轮“关系零输出”不能用于评价关系判断模型，主要瓶颈已定位在候选覆盖与实体筛选。

24 份真实产物全部通过适配及来源验证，36 项回归通过。预先冻结的扩大门槛未通过，停止扩大，不替换默认 v6。下一步应优先建立覆盖更完整、与评测文档隔离的实体候选生成器，并在小规模上分别验证候选覆盖率、实体保留率和关系判定；不再用完整流水线的零输出掩盖阶段未执行。
