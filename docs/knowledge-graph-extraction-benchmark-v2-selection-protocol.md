# 参考标注协议 v2：逐字片段与位置交叉校验

旧协议仅要求模型选全字符索引，程序据此切片并检查坐标合法。原文抽查发现这允许模型把“compaction”选为“mpaction”，也允许裁决请求只见索引、不见物化后的候选词。新协议另起版本；旧的校准参考、请求及哈希保持不变。

## 片段格式

模型必须同时给出原文引用和 Unicode 左闭右开位置：

```json
{"block_id":"chunk","quote":"soil compaction","start":5,"end":20}
```

接收端先确认 `quote == source[start:end]`，再根据原文计算出现序号，并用旧来源跨度校验器验证重建一致。不自动移位、不修拼写、不去噪，也不把双引号或标点自动裁掉。start/end严格为整数、start允许0、end不超过该块长度。

该交叉校验能拦住引用和位置不一致，不能证明选择的片段在语义上正确。因此裁决输入必须明确显示每个候选的实际文本、坐标、完整正文和断言窗口；复核者逐项判断实体是否完整、类型是否符合范围、关系谓词/方向/条件是否受证据支持。模型自己的索引不能当证据。

## 关系证据

保留端点身份引文与关系断言窗口两个字段。断言窗口应是连续原文片段，包含足以判断关系谓词、方向、否定和适用条件的上下文；仅重复端点词不能通过语义审核。不能跨题名、正文、页面栏或参考文献拼出单一断言。解析文本无法确定阅读顺序时，记录受影响的任务为待裁决；未经来源证据不能自动扩大排除掩码。

## 协议验证范围

第一步是离线接口验证与新合成控制题，包括：位置引用互相矛盾、英文词内部截断、汉字边界、重复短语、多字节字符、越界位置、标题身份引用、端点词误作关系、实验室方法误作田间治理，以及双栏/图表残片。拒绝项要保留原预测，不自动修正为合法实体。

第二步才在已有失败文献与新开发文献上做小规模双标、物化后来源复核和错误分解。模型请求不接收旧裁决结果；新复核者可以看候选的逐字表面，不只看选择代码。真实错误在来源裁决后形成另一个有版本号的参考修订，不能写入冻结100条。

小样本需要同时报告：引用/位置一致率、实体边界与类型错误、关系断言支持/谓词方向错误、共同遗漏、输出完成率和来源无法判定率。控制题通过只验证协议的可操作性，不能证明真实来源总体正确。专家认证范围不变，当前 AI 复核仍具有相关错误风险。
