# M3 容量与运行目标建议（待确认）

日期：2026-10-30。依据M2真实112168块实测提出，尚未冻结、尚未运行10k/100k、不构成容量通过。用户确认资源和数值后才按本口径执行；不扩大模型预算、不做生产回填或部署。

## 规模与资源

按现有1173份混合文献/112168块，平均约95.6块/文献；10k约95.6万块，100k约956万块。使用现有文献分布构造独立ID、独立命名空间的可重现合成负载，并单列长文档、重复内容和权限分布。原库仅642篇论文，不能将这些重复构造的数据称为十万篇真实论文或真实抽取覆盖。

原Chroma一致克隆约1.458 GB，新增FTS派生库约0.435 GB，简单按文献比例放大：10k约16.1 GB、100k约161.4 GB，未含WAL、临时构建、备份、PG研究记录或更多图数据。这只是当前分布的线性存储预估，不能作为100k实测。1024维float32向量本身约39 GB/100k，也不等于HNSW实际常驻内存。

建议10k先用现有16逻辑CPU/16 GB机器，单写入worker，预留SSD至少60 GB；若内存或延迟触及限制，保留失败并调整方案。100k需独立机器或经确认的资源：起步16核、64 GB RAM、SSD空闲至少500 GB；是否需128 GB、索引分区或后端调整，依据10k实测和HNSW实际驻留决定，不保证64 GB足够。当前机器未做100k运行授权，也不自动安装平台或购置资源。

## 建议冻结的测量口径与目标

| 指标 | 10k建议目标 | 100k建议目标 |
| --- | --- | --- |
| 已有索引启动（进程到可检索，不含全应用） | ≤30秒 | ≤120秒 |
| 常态启动全库正文读取/重新分词 | 0/0 | 0/0 |
| 原文检索HTTP P95，limit=5，含当前来源校验 | ≤3秒 | ≤5秒 |
| 词法后端P95，limit=20 | ≤2秒 | ≤3秒 |
| 混合后端P95，不含embedding/重排/生成 | ≤5秒 | ≤8秒 |
| 102块单篇删除后重放，不含模型生成 | ≤10秒 | ≤20秒 |
| 元数据更新正文重新分词 | 0条 | 0条 |
| 工作集/进程private bytes停止线 | 任一超过10 GiB停止本批 | 任一超过可用RAM的75%停止本批 |
| 恢复一致性 | 所有已完成写入可重放、计数一致、pending最终0 | 同左 |
| 来源/权限变化、取消、重复任务 | 不返回失效正文、不越权、不重复提交 | 同左 |

阈值是建议，不按最终成绩下调。P95至少200次请求，固定32个查询（含中英文、常见词、稀有词、无命中），首次冷查询与热重复分开；先并发1，再并发2/4。预先固定查询、种子、排序版本、过滤和每次候选/来源核验预算。真实向量重放只验证HNSW成本，语义质量另行报告。HTTP需使用真实当前来源与哈希校验，不拿内存模拟adapter作为上线延迟成绩。

运行上限建议：10k单批最多60分钟，100k最多8小时，每60秒记录阶段进度和资源；一次最多执行一个容量阶段，达到内存、磁盘或时间停止线先保存进度，禁止自动扩容续跑。保留异常批次；不静默删除难文档、缩小规模或减少来源校验。并发增加只测量，不能修改20/100任务准入默认值来掩盖积压。

## 顺序、恢复与完成定义

1. 确认目标机器、SSD空闲、测量上限和上述数值；冻结独立容量清单、版本、种子、文献/分块分布。先不调用模型，不创建新参考答案。
2. 10k测量首次构建、暖启动、增量/删除、并发检索、权限变化及崩溃恢复；分别统计Chroma向量、词法行、研究记录、任务和图关联。现有语义覆盖只能保持真实十篇/两条，不复制成已验证事实。
3. 检查10k资源和长尾，再决定100k资源及必要工程调整。若需要变更已冻结目标，必须在100k运行前说明并确认；不根据100k结果修改通过标准。
4. 100k按同一口径运行，报告构建成本、P50/P95/P99、IO、工作集/private bytes、积压、恢复时间及计数。图后端若仍未部署，图容量明确未完成，不能用JSON或伪造图成绩替代。
5. 单列三个结论：管理/检索容量，真实已抽取论文与记录数，已审核发布事实数。M2后两者仍分别为十篇部分任务抽取/两条pending、发布0。拒绝把合成容量折算为语义成果。

完整论文抽取的单位token、费用、有效记录产出和持续吞吐仍未知，M2没有新增模型样本。后续如要扩大抽取，应单独定义任务相关小批次及预算用途，依据M1的27条错源选择先改善可接受产出，再决定覆盖；这不作为本次容量压测的隐性前提。
