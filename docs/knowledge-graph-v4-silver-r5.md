## 序号与质量路由修正

`fragment.occurrence` 是相同文本在同一块中从 0 起的出现序号，不是实体列表序号。程序按原文定位，可用明确的原文锚点选择重复出现的位置。只允许空白对齐，不改字母、大小写、标点和 OCR 字形。最终存储原文半开区间 `[span_start, span_end)` 和文本哈希；审核页面行号从 1 起，JSON 的 `index` 从 0 起，不能混用。

新增 `annotation_tasks_r5.annotate`，复用统一分阶段协议并加入明确序号说明。模型质量判断仅是建议：即使模型报不可读，或质量阶段解析失败，仍尝试定位实体、规范化和有合法候选时的关系判定；实体阶段失败则保留失败状态，不能伪装完成。提议状态为 `needs_review`，完整性不确认，不会自动变成可评分银标。历史 r4/r4.1 默认行为、历史响应和旧分数保留。

逐条裁决独立设置 `eligibility_by_block`，分别控制正文实体、正文关系和题名实体。评分器把参考掩码同时用于参考与预测；模型自己报不可评不能躲掉漏抽取，被排除正文中的预测也不会被计作误报。仅题名可评不能使损坏正文成为正确负例。

## 本轮裁决规则

- 来源优先：只判可见正文及题名。题名主要提供标准身份；论文主题不能补成正文关系。孤立标准实体仍保留，不能因为没有治理关系而删除。
- 正文媒介必须明确：食品、植物、试剂、水体、制造材料的检测属性不当土壤指标。介质不明时排除任务，不当完整负例。
- 土壤管理与修复措施包括明确的实验性土壤干预，分析提取、PCR、校准和材料制造不算。名录中的植物种名不自动成为已实施的修复措施。
- 目录、参考文献和出版元数据不当正文实验事实。缺表头、双栏交织、字符映射损坏或关键截断无法穷尽时，保留可读候选并排除对应任务。
- 只选最具体、原文充分支持的关系。共现、考虑因素、显著性、预测精度提高不等于土壤改善。丰度升降本身不代表有益，不把联合处理效果分配给单一组分。
- 缩写及其全称只有原文明示等价时才标 `known` 并保留证明；其他规范化为 `unknown`，不能按猜测补全后评分。

本轮标的是**代表性原文实体清单**，不是全文每一次重复提及的穷尽标注。主指标按块、类型、去空白后的原文表面形式去重，关系端点采用相同键；相同文字换到另一处可核验的原文位置不应变成错误。不同名称、大小写、标点、OCR 字形仍不自动合并，别名规范化另评。原有严格位置指标保留作诊断，不得将其直接称为穷尽式 NER 准确率。

## 数据与评测入口

目录：`artifacts/knowledge_platform/gold-v4/silver-v1/`。

- `reference.jsonl`：冻结的 100 条来源、裁决、跨度、分任务掩码和来源链。
- `source-adjudications.jsonl`：逐条理由、原始裁决选择及编译结果，可重新校验。
- `exclusions.jsonl`：逐项排除范围、理由和不确定性。
- `manifest.json`：统计、版本、输入与参考哈希，开发集及曝光声明。
- `review.html`：静态逐条审核页面，含完整可见原文、位置、候选、关系证据和评分范围；来源文字经过 HTML 转义，无网络资源。
- `source-validation.json`、`release-verification.json`：绑定、重建、评分掩码及历史哈希校验。

参考 SHA256：`5d14be8c4bcaed74bf9ccf0e68e395b4f19a7bb77291a59b4eb1489c1791430f`。冻结后不得原地修改标签；发现问题应新建版本并记录差异。

预测 JSONL 每行使用 `{"sample_id":"…","input_sha256":"…","answer":{…}}`，`answer` 遵守 v4/r3 的五字段结构 `quality/mentions/relations/completeness/notes`，片段仍为 `block_id/text/occurrence`。实体 ID 必须在本行唯一，关系使用本行 ID。输入哈希从冻结参考读取。建议让 r5 产生提议，再做来源审核；不能直接把模型提议当新参考。

```powershell
.venv/Scripts/python.exe scripts/score_kg_silver100.py --predictions <预测.jsonl> --output <评分.json>
.venv/Scripts/python.exe scripts/verify_kg_silver100.py
```

未知或重复样本、输入哈希不符会阻止评分；格式错误作为无有效预测记录，并在可评分任务上累计漏报；缺失预测不会被丢弃。报告包含全部 100 条、有效完成率、各任务可评分数、正文与题名分数、文档宏平均和聚类区间。主指标是 `surface_chunk_mentions`、`surface_relations`；`surface_context_mentions` 单列，不能用题名抬高正文结果。原文证据的语义充分性仍需独立复核，字符匹配不能证明事实正确。

## 验证与剩余限制

本轮纯本地测试：

```powershell
.venv/Scripts/python.exe -m pytest --noconftest tests/test_kg_silver_adjudication.py tests/test_kg_annotation_tasks_r4.py tests/test_kg_annotation_tasks_r41.py tests/test_kg_evaluation_v4.py tests/test_kg_evaluation_v4_r3.py -q
```

结果 36 项通过。`--noconftest` 用于避开全局应用和数据库初始化，这些测试不需要数据库；最初包含全局初始化的运行阻塞，已中止。验证脚本重建全部 100 条、核对跨度与输入、确认 9 个历史文件哈希不变；空预测探针保留 100 条分母，正确累计 211 个正文实体漏报和 27 条关系漏报，正确负例为 0。探针是评分契约验证，**不是模型准确率评测**。r5 的质量失败和误判分支用模拟响应测试，尚无新的云端资格验证。

这份银标由单一 Codex 裁决，已接触历史标签，没有独立双标和专家仲裁。可用于有限开发回归与错误分析；不开放自动扩展到其余 900 条，不认证盲测、生产验收或整体 GraphRAG 问答效果。下一步应使用固定输入做一轮预注册开发对照，分开报告正文实体、关系及排除覆盖率；损坏来源的重新解析、更多关系正例、独立复核及未曝光测试集需另行建设。
