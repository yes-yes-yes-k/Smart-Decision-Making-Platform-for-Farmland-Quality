# Cd 双模型数据需求清单

> 给业务/数据方的需求说明。目的：让本项目能在**自有地块数据**上跑通 Cd 双模型预测。
> 现状：2026-10-31 实测，本项目 5488 个地块能凑齐模型输入的**数量为 0**（详见 `docs/cd-input-coverage-report.md`）。

## 一、为什么需要这份数据

两个模型都是**固定维度输入**的神经网络，缺任一特征就无法预测（不是"少一点精度"的问题，是直接拒绝）：

- 作物 Cd 模型 `crop_cd`：14 个特征
- 土壤有效态 Cd 模型 `effective_cd`：21 个特征

模型资产已就位并在本地跑通，与原系统结果**逐位一致**（见 `docs/cd-model-consistency-report.md`）。唯一缺的是地块级输入数据。

## 二、交付形式要求

- **格式**：CSV（UTF-8）或 Excel，一个模型一张表（两张表可合并为一张，用 `model` 列区分）
- **主键**：`parcel_id` + `sample_id`
  - `parcel_id` **必须与现有 `parcel_info.parcel_id` 同一体系**（当前是 1..999 的纯数字字符串），否则无法与地块主表、行政区、几何关联
  - 一个地块一个样点时，`sample_id` 填 `0` 或与 `parcel_id` 相同均可，但需在字段字典里说明
- **一行一个（地块, 样点）**，不允许合并单元格、不允许合计行
- **必须附字段字典**：每个字段的中文名、单位、取值来源（实测/插值/区域回填/默认值）
- **必须附覆盖说明**：这批数据覆盖哪些乡镇、共多少地块、与 `parcel_info` 的匹配率

## 五、数据质量要求

- **单位必须统一并写明**：同一字段全表同一单位，混合单位直接拒收
- **数值范围**：请提供合理上下限；出现 0、负数、明显异常值时请标注（模型对异常值不做剔除）
- **缺失标记**：用空值表示缺失，不要用 `-9999`、`0`、`N/A` 等占位（会被当成真实值参与计算）
- **来源标注**：每个字段请说明是"地块实测 / 空间插值 / 区域均值回填 / 默认值"——本项目会据此决定结果是否标记为降级
- **时间点**：注明调查年份；不同年份数据不要混在一张表里

## 六、覆盖范围与优先级

1. **第一批（试点）**：1–2 个乡镇、≥200 个地块，字段齐全率 100%，用于打通全链路
2. **第二批**：目标覆盖 `parcel_info` 全集（5488 个地块）中至少 80%
3. 不接受"先给一部分字段"——模型是固定 14/21 维，缺一个字段等于该批数据全部不可用（除非只给试点地块的完整行）

## 七、验收方式（我们会做的检查）

数据到手后我们会跑：

- 与 `parcel_info.parcel_id` 的匹配率（要求 100%，未匹配的行不计入）
- 每个模型的字段齐全率（要求目标地块 100% 齐）
- 数值合理性（非空率、异常值、量级）
- 试点批次端到端跑通：输入 → 预测 → 结果落库 → 统计/明细/导出可查

任一项不达标会把问题清单返回，不会带着缺陷数据出结果。

## 八、特别说明：`solution` / `cdsolution`

这两个字段不是土壤实测值，是**上游 MSM 络合模型的输出**经公式转换而来：

```text
solution = LN(POR_Layer / bd020_90 × 112000 × Cd.solution)
```

原系统里它们由 MSM 模型先算好存表，Cd 模型只读。所以**这两个字段要么由数据方一并提供，要么需要我们先集成 MSM 模型**（原系统仓库不含 MSM 求解代码）。请明确走哪条路。
