# 检索质量与真实图关联实施任务 v1

日期：2026-10-30。依据[已确认计划](knowledge-engineering-retrieval-quality-plan-v1.md)及[ADR-0004](adr/0004-domain-constraints-with-reusable-backends.md)。本文细化实施，不表示任务已执行。勾选状态统一维护在[OpenSpec tasks](../openspec/changes/enable-literature-evidence-comparison/tasks.md)，避免两份进度互相冲突。

## 执行顺序与完成口径

关键依赖：R0 → R1、R2 → R3隔离贯通 → R4本机验收。R3启动副作用审计和迁移设计可提前进行；图价值对照必须等待强检索基线与真实持久图路径都可运行。优先完成一个来源的纵向闭环，再扩大至原十篇，不把所有模块开发完才首次联调。

每项完成必须附代码/文档位置、实际验证命令、结果和限制。实现存在、离线测试通过、真实来源验证通过、本机启用分别记录；历史M1/M2不自动满足新增任务。遇到缺失原文、未核实支持或服务不可用，记录阻塞与可继续的任务，不把困难样本删除。

计划新增产物目录为 `artifacts/knowledge_platform/retrieval-quality-r1/`，按运行ID另建目录，登记输入和配置哈希。本文的文件名是待交付约定，不是已经存在的结果。不修改历史冻结产物。

## 预算与验证约束

- 无模型任务先推进；模型预算按实际待发送请求预留输入与输出，调用尝试和失败计入账本。历史M1剩余额度、外部评测额度不自动转用。
- 新批次方案需覆盖抽取、嵌入、重排和语义核实等实际调用，明确停止条件。达到授权上限保存进度并停止，不后台续跑。
- 必要测试聚焦跨模块行为：来源隔离、跨度验证、跨试验错误关联、候选身份、持久化重启、幂等恢复、图失败回退、真实排序。不编写仅镜像实现的测试。
- 优先使用隔离环境，避免根测试初始化正式数据库；每次报告实际运行的命令与未覆盖部分。
- 现阶段不承诺整体工期。R0完成后依据错误量、R2请求清单及调用吞吐给出分阶段估时；外部服务等待与实际开发耗时分别记账。
