# 广东耕地地图后端改进清单

## 1. 文档目的

本文档根据当前广东耕地地图的用户反馈，整理后端可以直接改进或需要为前端提供支撑的事项，作为需求评审、任务拆分和开发验收依据。

纯前端事项，例如区域选择控件的位置、边界线宽、图表标题展示和鼠标悬浮行为，不作为独立后端任务；但后端应提供完成这些交互所需的数据和接口。

## 2. 当前情况摘要

- 广东行政边界源数据包含 L0–L4 层级，其中镇级边界文件为 `Guangdong_L3_TXZQ.shp`。
- 2026-09-18 已完成韶关市范围 L0–L4 入库：1 个省级、1 个市级、10 个县级、103 个镇级、1199 个普通村级区域，以及 373 个村界争议区，全部具有合法几何。
- 导入工具已支持 `lechang`、`shaoguan`、`guangdong` 三种范围；广东全省 21 个地市已完成流式 dry-run，但尚未写入当前数据库。
- 当前数据库包含 5488 个地块。质量等级、pH、有机质、有效磷、速效钾、土壤容重、耕层厚度和有效土层厚度所映射的源字段均有值。
- 聚合统计、地块详情和经纬度点选接口均已支持全部 8 项指标；详情响应同时返回等级、区间和颜色。
- 后端已经维护指标名称、单位、分级阈值和颜色，但地图、柱状图和环形图尚未完全统一使用该配置。

### 2.1 P0 推进状态（2026-09-18）

| P0 项目 | 状态 | 落地结果 |
|---------|------|----------|
| 补齐 L0–L4 行政边界 | 已完成（韶关范围） | 省、市、县、镇、村均有几何；父级缺失数为 0 |
| 扩大镇域边界范围 | 已完成（韶关范围） | 镇级区域由乐昌 17 个扩展至韶关 103 个 |
| 补全地块详情指标 | 已完成 | 详情和点选接口返回全部 8 项指标及统一分级信息 |
| 统一厚度字段 | 已完成兼容迁移 | 5488 个地块已补齐 `effective_soil_depth`，旧字段继续保留 |

广东全省 dry-run 共校验 1 个省、21 个市、123 个县级、1716 个镇级、24858 个普通村级区域和 1327 个争议区；修复 3 个镇级、16 个村级无效几何，并为源数据中的直属管理占位补建 2 个不可选择的县级父节点和 4 个不可选择的镇级父节点。当前数据库仍只启用韶关市范围，避免未经业务确认直接扩大线上数据范围。

## 3. P0：数据与接口完整性

### 3.1 补齐广东 L0–L4 行政区边界

**状态：已完成韶关市范围；全广东导入能力已具备但未写库。**

**当前问题**

当前导入程序主要读取县、镇、村三级边界。广东省和韶关市虽然在区域目录中存在，但属于无几何的占位记录，不能用于地图展示和空间统计。

**改进内容**

- 导入 L0 省界、L1 市界、L2 县界、L3 镇界和 L4 村界。
- 建立完整的父子关系：省 → 市 → 县 → 镇/乡/街道 → 村。
- 明确本期数据范围是乐昌市、韶关市还是广东全省。
- 对每一级边界执行坐标系、空几何、无效几何、重叠和覆盖完整性检查。
- 保留争议边界，但标记为不可直接选择的 `zone`，不得强行归入普通行政村。

**验收标准**

- 目标范围内 L0–L4 记录均已入库。
- 除明确标记的占位或争议记录外，各行政区域均有合法几何。
- 可通过父级 ID 逐级查询下级区域。
- 省、市、县、镇、村边界均可参与空间相交和区域统计。

### 3.2 扩大镇域边界导入范围

**状态：已完成韶关市范围。**

**当前问题**

历史导入逻辑只处理乐昌市代码 `440281`。当前已改为可选择乐昌、韶关或广东范围，并已将韶关市 103 个镇级区域写入数据库。

**改进内容**

- 根据最终业务范围导入韶关市或广东省全部镇、乡和街道边界。
- 保留标准行政区划代码和名称。
- 建立镇级区域与所属县区的父子关系。
- 增加重复编码、孤立父级和跨县几何异常检查。

**验收标准**

- 业务范围内全部镇、乡和街道可查询。
- 每个镇级区域都有县级父节点和有效几何。
- 镇域可独立用于地图定位、筛选和统计。

### 3.3 补全地块详情和点选接口指标

**状态：已完成。**

**当前问题**

地块详情和经纬度点选接口目前只返回：

- 耕地质量等级
- 有机质
- 土壤 pH
- 有效磷

缺少：

- 速效钾
- 土壤容重
- 耕层厚度
- 有效土层厚度

**改进内容**

- 地块详情和点选接口统一返回全部 8 项指标。
- 每项指标同时返回原始值、单位、等级、阈值区间和颜色。
- 指标缺失时字段保留并返回 `null`，不得直接省略。
- 聚合接口、详情接口和点选接口使用相同的指标定义模块。

```json
  "metrics": {
    "quality_grade": {
      "value": 8,

      "bucketKey": "grade_8",
      "bucketLabel": "8等",
      "rangeLabel": "8等",
      "color": "#F46D43"
    },
    "organic_matter": {
      "value": 19.18,
      "unit": "g/kg",
      "bucketKey": "medium_low",
      "bucketLabel": "中低",
      "rangeLabel": "(10,20]",
      "color": "#FC8D59"
    },
    "available_potassium": {
      "value": 82.5,
      "unit": "mg/kg",

      "bucketLabel": "中低",
      "rangeLabel": "(50,100]",
      "color": "#FC8D59"
    }
  }

```

**验收标准**

- 两个地块查询接口都返回完整 8 项指标。
- 同一指标在聚合、详情和点选接口中的单位、等级与颜色一致。
- OpenAPI 和接口文档同步更新。

### 3.4 统一土层厚度相关字段命名

**状态：已完成规范字段和兼容回退；业务术语仍应在后续数据治理中持续核实。**

**当前问题**

历史数据存在 `topsoil_thickness`、`effective_soil_depth`、`plow_layer_thickness` 和 `plow_layer_depth` 等相近名称。当前已将 `effective_soil_depth` 设为有效土层厚度规范字段，并将历史 `topsoil_thickness` 保留为兼容别名；耕层厚度使用 `plow_layer_thickness`。

**改进内容**

- 明确以下指标的业务定义和标准字段：
  - 耕层厚度
  - 表土厚度
  - 有效土层厚度
- 确认源数据字段与业务指标的真实对应关系。
- 建立兼容映射，但接口只暴露一套标准命名。
- 在接口元数据中增加中文名称、单位和数据来源说明。

**验收标准**

- 数据库映射、接口字段和文档术语一致。
- 不再由两个不同业务概念共用同一个含义不明确的字段。
- 历史客户端仍可通过兼容层正常调用。

## 4. P1：地图边界与区域选择能力

> 推进状态（2026-09-18）：已完成首版后端实现和真实 PostGIS 联调。已提供 GeoJSON 边界接口、同级多行政区联合统计和 Polygon/MultiPolygon 统计；接口契约、限制条件与测试已补齐。后续仍可按实际数据量升级为矢量瓦片和补充性能压测。

### 4.1 增加行政边界数据接口

**当前问题**

现有区域目录接口主要返回行政区名称、代码、父级和 `hasGeometry`，不直接返回边界几何。若前端没有独立的地图服务，就无法仅依赖该接口绘制市界、县界、镇界和村界。

**改进内容**

- 增加 GeoJSON 或矢量瓦片边界接口。
- 支持按行政层级、父级区域、地图范围和缩放等级查询。
- 返回行政区代码、名称、层级、父级和是否可选择等属性。
- 数据量较大时优先采用矢量瓦片，并按缩放级别简化几何。

**建议接口**

```http
GET /api/v1/farmland-statistics/boundaries
    ?region_type=township
    &parent_type=county
    &parent_id=440281
```

**建议返回元数据**

```json
{
  "regionType": "township",
  "regionId": "440281001",
  "displayName": "乐城街道",
  "parentType": "county",
  "parentId": "440281",
  "selectable": true,
  "minZoom": 9,
  "maxZoom": null,
  "geometry": {}
}
```

**验收标准**

- 前端无需内置行政区边界文件即可绘制目标区域。
- 可按层级和父级加载边界。
- 村界可配置为仅在较大缩放级别返回或显示。

### 4.2 支持多行政区联合统计

**当前问题**

现有行政区统计一次只接受一个 `region_type` 和一个 `region_id`，不能直接统计多个不连续区县。

**改进内容**

- 增加 `administrative_regions` 范围类型。
- 接受同级行政区 ID 数组。
- 使用 PostGIS `ST_Union` 合并所选区域后再裁剪地块。
- 响应中返回参与统计的行政区列表。
- 对不同层级混选制定明确规则，首期建议只允许同层级多选。

**建议请求结构**

```json
{
  "scope": {
    "type": "administrative_regions",
    "region_type": "county",
    "region_ids": ["440281", "440282"]
  },
  "metrics": "all"
}
```

**验收标准**

- 可同时选择多个不连续区县或乡镇。
- 地块数、面积和指标统计基于合并后的真实边界，而不是外接矩形。
- 重叠边界不会造成面积重复计算。

### 4.3 支持自定义多边形统计

**改进内容**

- 在现有行政区和视口 bbox 之外，增加 Polygon/MultiPolygon 范围类型。
- 校验 GeoJSON 几何类型、坐标范围、环方向和几何合法性。
- 对复杂几何设置顶点数和面积限制，防止超大空间查询拖垮服务。

**验收标准**

- 用户可按圈选区域进行非矩形空间统计。
- 无效几何返回明确的业务错误。
- 查询使用现有 GiST 空间索引，并满足约定的响应时间。

## 5. P1：统一阈值、颜色和地图属性

> 推进状态（2026-09-18）：已完成。指标配置、聚合结果和地块详情共享同一指标定义，并返回 `classificationVersion=2026-09-18.1`；地块指标对象补充 `metricKey`，已有字段保持兼容。

### 5.1 建立唯一指标配置来源

**目标**

地图图斑、地图图例、柱状图和环形图必须使用同一套后端指标配置，避免阈值和颜色不一致。

**改进内容**

- 继续以指标定义模块作为名称、单位、精度、阈值和颜色的唯一来源。
- 聚合结果、地块详情和地图要素统一返回：
  - `metricKey`
  - `value`
  - `unit`
  - `bucketKey`
  - `bucketLabel`
  - `rangeLabel`
  - `color`
- 增加 `classificationVersion` 或配置更新时间，便于客户端正确刷新缓存。
- 禁止地图专用接口自行维护另一套分级阈值或颜色。

**验收标准**

- 相同地块、相同指标在地图、柱状图和环形图中的等级与颜色完全一致。
- 修改一次后端指标配置即可同步影响所有展示渠道。
- 客户端可以识别配置版本变化。

## 6. P2：地块悬浮和点选支持

> 推进状态（2026-09-18）：已完成首版。点选接口支持单指标轻量响应和 0–50 米容差，增加 5 秒短时缓存及按用户限流；新增当前视口轻量地块 GeoJSON 接口。真实查询计划已确认使用 `idx_parcel_info_geom` GiST 索引。

### 6.1 优化点选接口

**改进内容**

- 返回全部 8 项指标及其等级和颜色。
- 支持传入当前指标 key，只返回当前展示所需的轻量信息。
- 可增加合理的点击容差参数，改善地块边界附近难以命中的问题。
- 检查空间索引执行计划，并增加短时缓存和访问频率保护。

**注意事项**

不建议浏览器每次 `mousemove` 都调用点选接口。优先方案是前端对已经加载的图层进行本地要素拾取；后端负责提供完整地块属性或当前视口内的轻量批量数据。若必须调用后端，前端应进行防抖和过期请求取消。

### 6.2 增加当前视口轻量地块属性接口

可选增加按 bbox 查询的轻量接口，仅返回：

- 地块 ID
- 当前指标值
- 等级 key
- 颜色
- 简化后的几何或质心

该接口可用于地图悬浮和专题图渲染，避免为每个地块单独请求详情。

## 7. P2：数据质量与来源追踪

> 推进状态（2026-09-18）：已完成首版。5488 个地块已回填 43904 条指标来源记录；地块详情、轻量点选、视口要素和聚合结果均返回来源信息。新增质量审计接口与离线报告脚本，耕层厚度常量值和有效土层厚度低变异已被标记。

### 7.1 增加指标质量检查

当前数据检查发现：

- 5488 个地块的 8 项指标均存在可解析值。
- 耕层厚度只有 1 个唯一值，全部为 `20 cm`。
- 有效土层厚度所映射的源字段只有 4 个不同值。
- 部分土壤指标可能来自区域平均值回填，而非地块级实测值。

**改进内容**

- 定期检查各指标的非空率、最小值、最大值、唯一值数量和异常值数量。
- 区分实测、模型估算、区域均值回填和默认值。
- 为指标增加以下来源信息：
  - `dataSource`
  - `measurementYear`
  - `isImputed`
  - `imputationMethod`
  - `qualityFlag`
- 对明显为默认值或缺乏空间差异的指标给出数据质量标记。

**验收标准**

- 可以追踪每项指标的数据来源和年份。
- 前端能够区分实测值与回填值。
- 后端可生成指标质量审计报告。

## 8. 不属于后端直接修改的事项

以下事项主要由前端实现，后端只需提供数据支撑：

- 将“区域限定”控件从地图右侧移动到左侧。
- 调整市界、县界、镇界和村界的线宽、线型与颜色。
- 根据地图缩放级别控制村界显示。
- 将柱状图标题从固定“等级分布”改为当前指标名称和单位。
- 增加“点击地块查看详情”的操作提示。
- 实现鼠标悬浮弹窗及其显示位置、延迟和关闭行为。

## 10. 总体验收目标

完成以上改进后，系统应满足：

1. 目标业务范围内具备完整、可查询、可统计的 L0–L4 行政区边界。
2. 地块详情、点选和聚合统计均支持完整 8 项指标。
3. 地图、图例、柱状图和环形图使用完全一致的阈值与颜色。
4. 用户可以按单个行政区、多个行政区、当前视口或自定义多边形进行统计。
5. 每项指标均可追踪数据来源，并能够识别实测值、回填值和默认值。
