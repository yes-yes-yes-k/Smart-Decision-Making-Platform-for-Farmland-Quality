# R2.5 D+C 阶段结果：只给引文 + 逐条编译

日期：2026-10-31。按 D → C 执行：模型只返回引文、坐标由服务端定位；单条失败不再作废整篇。**流水线首次跑通并产出候选**，但单篇成本仍是约 2.2 万 token，耗时 250 秒左右。

## D：协议与提示词改造

- 提示词改为 `{chunk_index, quote}`，不再要求模型算坐标；
- 服务端定位顺序：块内精确 → 块内空白归一 → 跨块唯一；**两次以上命中即拒收**（不猜位置）；
- 记录里保存的始终是**原文精确片段**，不是模型转述的排版；
- 新增 `compile_partial_quote_only`：逐条解析、失败的单独拒收并给原因码，只有可解析的子集进入冻结契约。

测试：`tests/test_selection_protocol_v2.py` 增至 **20 项通过**（新增字符串引文、跨块唯一、歧义拒收、逐条编译、研究上下文不可解析时整研究丢弃）。

1015 与 1141 的用量几乎相同（21.8k），其中**推理 token 占 85%**（18,646 / 21,854）。把坐标交给服务端计算，只把总量从 24.3k 压到 21.9k（−10%），**没有改变成本结构**。

## 结论

1. **链路通了**：真实模型输出 → 引文定位 → 逐条契约校验 → 本地候选，首次产出可审计的候选集。
2. **单篇仍约 2.2 万 token**：成本由推理开销决定，与是否要求坐标几乎无关。
3. **超时是第二道坎**：1032 连续两次 300s 超时，1021 在上一轮也两次超时。十篇里至少两篇需要更长超时或更小输入。
4. **拒收集中在两类**：引文歧义（同一短语在块内多次出现）与端点被拒后关系悬空。前者需要更长的唯一引文，后者可由逐条编译自然隔离。
