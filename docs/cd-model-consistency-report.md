# Cd 模型一致性与输入可行性报告（2026-10-31）

目的：在补"输入供给"之前，先回答两个问题 ——（1）本项目本地推理与原系统在线结果是否一致；（2）原系统输入表能否直接供本项目地块使用。

方法：只读连接 `soilgd`，按 AcidMap 的 ORM 列映射取真实输入行，喂本项目 `predict()`，与原系统输出列逐位比对。探针脚本用完即删。

## 一、结论先说

1. **模型迁移是正确的**：作物 Cd 的本地推理结果与原系统 `CropCd_output_data.LnCropCd` **逐位一致**（1000 行抽样，中位绝对差 `1.7e-07`，最大 `1.9e-06`）。
2. **原系统有效态输出列存在语义错误**：`EffCd_output_data.LnEffCd` 里存的其实是**浓度值**，不是对数值。本地的 `exp(log_prediction)` 与该列**逐位一致**（中位差 `1.6e-08`），而本地 `log_prediction` 与该列相差约 `-2.95`。
3. **原系统输入表不能直接供本项目地块使用**：两边地块 ID 体系不同（40100 vs 5488），按坐标匹配覆盖率极低（≤100m 仅 8.7%，中位距离 57km）。

## 二、模型一致性（逐位比对）

**作物 Cd（crop_cd）**

- 抽样 3 行：本地 ln 与原系统列值差为 `-0.000000 / -0.000000 / +0.000000`
- 1000 行随机抽样：`|本地ln − 列值|` 中位 `1.706e-07`、最大 `1.899e-06`；失败 0 行
- 说明：`LnCropCd` 确实是自然对数，本项目 `log_prediction` 与之等价

**有效态 Cd（effective_cd）**

- 抽样 3 行：原系统列值 `0.055269 / 0.055334 / 0.055223`，本地 ln `-2.895538 / -2.894372 / -2.896377`，本地**浓度** `0.055269 / 0.055334 / 0.055223`
- 1000 行：`|本地浓度 − 列值|` 中位 `1.616e-08`、最大 `1.688e-07`；`|本地ln − 列值|` 中位 `1.689`
- 说明：该列名为 `LnEffCd`，实际存的是 `exp(ln)`，即浓度。原系统写入路径 `_save_predictions_to_database` 接收的参数已是 `np.exp(predictions)`，直接写进列里，未再取对数

**这解释了此前的"量级不符"疑点**：`exp(LnEffCd)` 会得到 1.0–2.3（因为对已经是浓度的值又 exp 了一次）；真实有效态 Cd 浓度是该列原值，落在 0.004–0.83 mg/kg，量级正常。

## 三、列名与语义的一个坑（必须记住）

`CropCd_input_data` 的 ORM 与 DB 列名是**交叉**的：

- ORM `available_potassium` = DB 列 `AvaP_IDW`
- ORM `available_phosphorus` = DB 列 `AvaK_IDW`

原系统构造 DataFrame 时用 `'AvaP': row.available_phosphorus`（取 AvaK_IDW）与 `'AvaK_IDW': row.available_potassium`（取 AvaP_IDW），即模型第 4 个特征（AvaP）的值来自 DB 的 `AvaK_IDW`。

按"名字直取"会取反这两列，导致作物 Cd 结果稳定偏 `+0.38`（ln），这正是第一版探针的偏差来源。修正映射后逐位一致。

有效态表没有交叉（`available_potassium` = `AvaK_IDW`、`available_phosphorus` = `AvaP_IDW`）。

## 四、输入表能否供本项目使用

两边规模与坐标：

- `soilgd`：`Farmland_data` 40100 个点（`Farmland_ID` 1..40100，`Sample_ID` 全为 0），`CropCd_input_data` / `EffCd_input_data` / `MSM_output_data` 各 40100 行
- 本项目：`parcel_info` 5488 个地块（`parcel_id` 纯数字、最大 999），全部有质心

KD-tree 最近邻（地块质心 → 原系统样点）：

- P10 = 121.6 m；P25 = 19.3 km；**P50 = 57.2 km**；P90 = 114.4 km
- ≤10m：8 个（0.1%）；≤50m：215 个（3.9%）；**≤100m：477 个（8.7%）**；≤300m：752 个（13.7%）；≤1000m：826 个（15.1%）
- ≤100m 内没有一对多共用样点

结论：**原系统的 40100 个样点与本项目 5488 个地块基本不是同一批位置**，只有约 9–15% 空间接近。用坐标匹配导入会产生大量张冠李戴的结果，不可采纳。

## 五、对后续的意义

- 模型层：可信。本项目 `heavy_metal_cd.predict()` 与原系统在线结果等价（作物逐位一致、有效态按列语义换算后逐位一致）。
- 数据层：本项目地块缺 Cd 模型的绝大部分输入特征（阶段 1 实测两模型可凑齐地块数均为 0），且原系统数据也补不上（位置不重合）。
- 因此"让结果表有真实数据"这件事**在当前数据条件下无解**，需要业务方提供本项目地块级输入，或在 MSM/插值数据源上补齐。
- 「`unit_status=unverified`」的依据可以更新：有效态的单位与量级疑点已被解释（原系统列语义 bug），真实浓度量级正常。是否升级为 `verified` 需单独建 change（阶段 1/2 已归档）。
