# M2 现有语料增量运行结果

日期：2026-10-30。M2实现和隔离验证完成；尚未部署，也没有证明十万篇容量或抽取质量达标。数据和运行证据在 `artifacts/knowledge_platform/operations-m2-v1/`，下一阶段建议见 `knowledge-engineering-m3-capacity-proposal.md`。

## 实际范围

原库1173份文献、112168分块；642份登记为论文，不将其余标准等统称为论文。其中1144份/107505分块具备当前来源资格；29份legacy other/4663分块保留在原有检索集合，新证据检索不扩大其资格。使用原库只读快照以及完整Chroma/HNSW隔离克隆测量，无新增模型、embedding、抽取、生产发布或生产写入。

硬件为Windows 11、AMD64、16逻辑CPU、约15.19 GiB物理内存；PostgreSQL 17.4、Chroma 1.5.9、jieba 0.42.1、SQLAlchemy 2.0.51。Windows working set和private bytes分别记录，不混为同一内存指标。测量在同一主机顺序执行，受OS缓存、其他主机活动影响；不是独占硬件的统计认证。

旧基准只实例化旧BM25并读取一致正文快照，新运行包括真实Chroma启动与候选核验，因此启动和内存比较的进程范围不同。首次新建比旧启动慢；收益在持久化重启、增量维护及查询。旧基准首次运行因内存采样器参数错误被终止，保留失败记录，表中仅用修正后的完整运行。

混合检索使用一个原有持久化向量重放，验证真实HNSW后端成本；不表示语义查询质量，也不包含API生成embedding、重排或回答。HTTP检索采用词法路径，包含本机PostgreSQL批量元数据和实际PDF哈希；只测8次，不能当成大样本P95。全文检索的排序公式从rank_bm25变为SQLite FTS5 BM25，词形处理增加casefold和标点清理，检索排序可能变化；不宣称质量等价或GraphRAG增益。

## 实现与工作量边界

持久化派生索引为Chroma目录下 `lexical-index.sqlite3`，SQLite FTS5加原文、元数据及恢复日志。首次缺失/版本变更时每页最多500块流式建立；正常重启仅检查状态和计数。常态变更预先写入范围日志，再更新Chroma，最后事务同步该范围；正文哈希未变只更新元数据，不重新分词。异常会留下pending日志，重启或显式维护修复；未就绪的词法集合停止返回结果，原有混合检索保留向量回退。外部绕过本适配器写入造成数量差异时，才触发全量修复；同数量的外部改写在候选读取时重验并留下修复记录。

关键词候选返回前按其有限ID读取Chroma当前正文与元数据，再检查权限，旧内容/权限变更的行不返回。实测Chroma同时使用ids+where会导致每集合约1.1–1.2秒元数据扫描，改为候选ID读取后等价权限检查。新证据检索默认面向全库，每次至多90个候选，当前来源批量查询至多两轮，只对这些候选及最终返回文献读取原件、计算SHA256；不扫描或哈希全库文件。原件仍每次核验，不用stat缓存代替内容有效性。8次检索和队列实验合计哈希115次、约444.8 MB，包含同一文件重复校验；这是实际IO成本，后续扩大规模须继续测量。

`/sources`及语义比较仍只登记M1十篇、两个既有pending记录；`/search`扩大为当前合格来源原文，`/sources/<id>/chunks/<index>`可打开未登记试点文献（实测文献820）。条件字符串只作为请求上下文，原文检索明确返回未作结构化条件匹配；不把未知条件标成匹配，不自动增加抽取覆盖。

异步比较新增排队准入保护：每用户最多20个queued/running，全局100个；满时429，重复请求可复用已有任务，取消/完成释放容量。SQLite写事务、PostgreSQL事务级advisory lock序列化准入；并发测试证明不超额。默认30秒处理超时、60秒租约、最多3次领取保持不变。这些是保护限制，不是已冻结的业务SLO。PostgreSQL准入分支尚无真实多进程压测；本次真实队列写入均在隔离SQLite。

## 恢复、积压及信任边界

102块真实文献的幂等重放、权限撤回/恢复、延后同步及注入派生写失败后重启均通过。最终向量112168条、词法112168条、pending修复0，恢复后该篇正文、ID、元数据与操作前一致。失败分页不会被误当成完整范围、不会清掉修复日志。

隔离产品队列复用十篇原文、两个既有记录，不调用模型。11个任务计数：completed 7、cancelled 2、failed 1、invalidated 1，合计11；queued/running均0。覆盖排队取消、运行取消禁止旧结果提交、注入执行失败、租约过期后重新实例化领取（attempts=2），以及隔离候选拒绝触发结果失效。七次普通处理各0.233–0.271秒，但多数文献没有可用研究记录；不能据此推算完整论文抽取吞吐。来源文件更改、撤回、权限变化及候选状态失效由独立回归覆盖，原生产来源未为测试而修改。

58项独立unittest和23项已有兼容测试通过，日志及测试文件哈希见 `validation-v1.json`。没有启动原应用的隐式迁移或根pytest conftest。原库结束只读盘点仍1173份/112168块、1144份合格来源、KG表为空；原Chroma全部正文/元数据另与开始快照逐行核对。M1冻结82文件、外部历史冻结2327文件及两套原预算账本保持不变，见 `integrity-v1.json`。全阶段模型调用0、发布新增0。

## 运维与后续限制

本次仅在隔离命名空间完成真实当前数据规模的功能和成本验证，没有部署常驻API/worker，也没有进行多日持续服务、真实多进程写竞争或业务质量验收。上线仍需明确迁移及独立部署确认。无需AGE即可使用原文路径，图谱依旧未部署，不宣称已完成AGE发布试点。

派生库可从Chroma重建，回滚代码不要求删除或重建原向量；生产启用前备份并在隔离环境验证。只能在停写和确认目标路径后移走损坏的派生库，不触碰 `chroma.sqlite3` 和HNSW文件。已有`rebuild_bm25_indexes()`仅刷新待修复范围；改变版本或显式force才全量重建。大规模首次构建、外部写入、进程崩溃及存储不足仍应进入M3压力/恢复测试。

目前最重要的产品缺口仍是M1研究记录覆盖不足，以及部署和真实容量未验证。下一步应先确认M3资源与数值目标，然后隔离10k、再100k；不把本次性能修复当成抽取质量进展，也不恢复评测集开发或全量抽取。
