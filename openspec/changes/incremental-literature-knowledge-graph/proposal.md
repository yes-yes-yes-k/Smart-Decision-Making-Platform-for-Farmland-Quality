## Why

当前知识库已完成千篇级文献入库，但知识图谱仍是一次性脚本生成、人工核验并整体加载的静态 v0.4 JSON，既不会随论文上传更新，也无法作为面向 10 万级知识平台的长期运行架构。项目需要在保留耕地质量领域语义、证据和审核控制权的同时，复用成熟开源构图与图存储能力，逐步形成可横向扩展、可替换供应商、可持续演进的知识平台底座。

本 change 将“10 万级”明确为容量规划基线，而不是首期必须一次性导入的数据量：系统架构和验收工具 SHALL 能覆盖至少 100,000 份来源文档、100,000 个规范实体和 1,000,000 条关系证据；向量 chunk 数量按实际分块独立扩展，不允许通过全量内存加载完成日常更新或查询。

## What Changes

- 新增可扩展开源能力适配层：抽取器、图存储和任务执行均通过项目契约接入，不把领域 Schema、证据格式或审核状态绑定到单一开源产品。
- 首选接入 Microsoft GraphRAG 作为 Python 侧实体/关系候选抽取器，并保留 OpenSPG Builder 适配器与离线对照能力；两者输出必须转换为统一候选契约，不能直接写生产事实。
- 采用 PostgreSQL + Apache AGE 作为 10 万级目标图存储，复用现有 PostgreSQL 运维、事务和备份体系；当前 JSON v0.4 作为迁移源、兼容读取和审计导出，不再作为规模化生产图的唯一事实存储。
- 在已审核文献完成向量索引后，自动创建幂等图谱任务；抽取失败不回滚已经完成的文献入库。
- 固化版本化最小本体：实体类型、关系类型、方向约束、稳定标识、别名策略和证据契约。首期继承 v0.4 的 4 类实体和 10 类关系，不要求一次性设计完整领域图谱。
- 对候选执行实体消歧、端点/方向校验、重复合并、证据页码和原文哈希校验；未经允许的实体或关系类型进入本体扩展候选，不得直接进入生产图。
- 建立候选、审核和发布三层状态。抽取自动化，但首期所有新事实和证据追加必须经过管理员或领域专家审核。
- 使用追加式版本数据和原子 `active_release` 指针发布；新版本不复制整张生产图，切换和回滚不依赖百万级 JSON 重写。
- 提供任务/候选查询、审核、发布、回滚、单文档重跑和历史文献幂等回填能力。
- 文档撤回、删除或来源失效时撤销对应证据；只有失去全部有效证据的关系才进入待审核移除。
- 增加容量基准、抽取质量、任务吞吐、待审积压、查询延迟、发布差异和回滚状态等可观测指标及可重复压测工具。

## Capabilities

### New Capabilities

- `knowledge-platform-foundation`: 定义 10 万级容量口径、开源组件适配边界、Apache AGE 目标存储、版本化运行模型、可移植性和规模验收要求。
- `incremental-knowledge-graph`: 定义文献驱动的图谱候选抽取、实体消歧、证据治理、人工审核、增量发布、回滚和历史文献回填行为。

### Modified Capabilities

- `file-upload-management`: 文献审核通过并完成索引后，新增非阻塞、幂等的知识图谱更新触发行为，并向授权用户暴露图谱处理状态。

## Impact

- 入库服务：在文档 `completed` 事务提交后写入 outbox；上传 HTTP 请求不等待构图。
- 开源依赖：引入可选的 GraphRAG/OpenSPG 抽取适配器和 Apache AGE 扩展；所有依赖均需锁定版本、记录许可证和生成软件物料清单。
- 数据库：新增图谱任务、候选、证据、审核和发布关系表；Apache AGE 保存规范实体与关系，关系表保存工作流及证据审计。
- 图谱模块：新增 backend-neutral schema、抽取器接口、图存储接口、候选规范化和版本发布服务。
- API：新增管理员候选审核、发布、回滚和平台健康接口；扩展文档状态的 `knowledge_graph` 子状态。
- RAG：继续把图谱命中的证据解析回当前用户有权访问的向量 chunk；首期不替换 Chroma，但禁止新增代码依赖其私有内部结构。
- 运维：增加后台 worker、AGE 健康检查、分区/索引维护、备份恢复、容量压测、积压告警和分阶段双读/回滚方案。

## Non-Goals

- 不在本 change 中一次性设计耕地质量全部概念、因果链和跨领域本体。
- 不允许任何开源抽取器或大模型把未经审核的候选直接发布为生产事实。
- 不在本 change 中迁移现有向量数据库；向量层扩容由后续独立 change 处理。
- 不改变现有文献审核、公开发布和向量索引的成功语义。
- 不强制部署 OpenSPG 或 Neo4j 全套平台；本阶段以低侵入适配、可比较、可替换为原则。
- 不将图谱改造成权限旁路；图谱证据仍必须解析为当前用户有权读取的向量分块。
