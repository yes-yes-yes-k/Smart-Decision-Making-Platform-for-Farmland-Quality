## 上下文

`src/ai_culti_demo/diagnosis.py` 当前为 `problems`、`measures`、`regions` 以及它们的兼容别名返回固定数字。这些值最初用于前端联调，没有连接专业模型、监测序列、样本统计或价格数据，却会以普通 `status=ok` 的响应进入县域诊断和结果整理接口。顶层 `reliability.level=demo_stub` 无法约束只读取局部表格字段的客户端。

当前系统已经普遍采用 `degraded`、`simulated`、结构化来源和模型版本表达结果边界。本变更将县域遗留接口纳入相同安全原则，但不在本次实现新的县域治理效果预测模型。

## 目标 / 非目标

**目标：**

- 从活动县域诊断响应中移除无依据的固定周期、提升率、效果、成本和占比。
- 保留主题、定性问题、治理方向和推荐图层，使现有页面仍能展示安全内容。
- 让客户端能在字段附近识别定量值是否可用、为什么不可用，以及非空值的来源。
- 让诊断摘要完整继承诊断状态，不在二次加工时补造数字。
- 用自动化测试阻止联调占位数字或同类无来源定量值回归。

**非目标：**

- 不实现治理见效时间、产量提升、投资收益或价格预测模型。
- 不在本变更中接通完整县域 Model-1 至 Model-5 聚合工作流。
- 不删除县域诊断接口、治理建议或地图联动能力。
- 不修改专业模型算法、数据库结构或分析对象上下文协议。

## 决策

### 1. 保留兼容键，但不保留不安全的值

`period`、`improve`、`effect`、`cost` 和问题 `percent` 等既有键暂时保留，值统一改为 `null`。这样可以避免旧客户端因键缺失直接崩溃，同时明确旧数字已经不可用。

这是破坏性语义变更：依赖这些字段参与计算、排序或图表展示的客户端必须适配 `null`。不提供恢复旧占位值的查询参数或功能开关，因为那会继续暴露已确认的不安全行为。

### 2. 定性模板返回 HTTP 200 和 `status=degraded`

合法主题请求仍返回 HTTP 200，但当结果只包含模板化定性建议时，响应使用：

- `status: "degraded"`；
- `result_kind: "advisory_only"`；
- `reliability.level: "insufficient_evidence"`；
- `reliability.predictive: false`；
- `reliability.quantitative_available: false`。

不继续使用普通 `status=ok`，因为成功状态会让客户端忽略可靠性说明；也不使用 HTTP 4xx/5xx，因为请求本身合法，且仍有可展示的定性建议。

### 3. 字段附近携带定量元数据

含潜在定量字段的对象增加 `metric_meta`。每个字段至少包含：

- `status`: `available` 或 `unavailable`；
- `reason`: 不可用原因或 `null`；
- `unit`: 单位或 `null`；
- `source`: 数据或模型来源；
- `method`: 统计方法或模型标识；
- `model_version`: 适用时提供；
- `calculated_at`: 计算时间；
- `scope`: 数值适用范围。

当前模板结果的这些字段全部为 `unavailable`，原因使用稳定代码，例如 `validated_prediction_unavailable`、`validated_statistics_unavailable` 和 `price_basis_unavailable`。

未来只有 `source`、`method`、`calculated_at`、`scope` 完整，且数值通过类型与范围校验时，字段才能标记为 `available` 并返回非空值。顶层可靠性字段由所有定量字段状态汇总生成，而不是由调用方手工声明。

### 4. 使用集中式构造与响应校验

诊断模块使用辅助构造函数创建不可用指标元数据，并在返回前执行安全校验。校验覆盖 `problems`、`measures`、`treatments`、`regions`、`base_data` 及后续兼容别名：

- 非空定量值必须存在完整的 `available` 元数据；
- `unavailable` 字段的值必须为 `null`；
- 模板结果不得包含已知联调常量；
- 兼容别名只能从已经校验过的安全结构生成。

集中校验用于防止某个别名或后续重构重新复制旧数字。校验失败属于服务端契约错误，应记录日志并返回机器可读错误，不得静默放行。

### 5. 保留定性内容，但明确其不是预测

治理措施名称、原则性说明和推荐图层可以继续返回，因为它们用于导航和一般性建议。每个模板建议增加 `advisory_only: true` 和 `basis: "template_guidance"`，不得使用“预计”“可提升至”“见效”等预测性措辞。

固定重点区域、权重或效果如果没有真实空间统计依据，不再作为重点区域结论返回。`regions` 可以为空，并通过状态说明当前没有可验证的区域排序。

### 6. 诊断摘要传播状态而不升级可信度

`build_report_summary` 接受结构完整的 `ok` 或 `degraded` 诊断，但必须原样传播 `result_kind`、`reliability` 和定量不可用信息。摘要和行动项只能引用输入中的非空、已验证值；不得根据 `null` 字段推断周期、效果、成本或占比。

无结构化状态、来源不一致或安全校验失败的诊断仍拒绝生成摘要。

### 7. 测试同时验证正向结构和负向禁令

测试除验证接口可用外，还要递归检查所有响应分支：

- 禁止出现旧固定数字和周期字符串；
- 禁止 `unavailable` 与非空值并存；
- 非空定量值缺少溯源时必须失败；
- `measures`、`treatments`、`regions`、`base_data` 语义一致；
- 摘要不得恢复被清空的数字；
- 无效主题继续返回原有机器可读错误。

## 风险 / 权衡

- [旧前端可能对 `null` 做数值运算] → 先更新接口文档和前端展示逻辑，使用“暂无可靠估计”占位，并在发布说明中标记破坏性语义变更。
- [将 `status` 改为 `degraded` 影响仅接受 `ok` 的消费者] → 同步更新核心引擎和结果整理适配器，并增加契约回归测试。
- [字段级元数据增加响应体积] → 只为潜在定量字段提供简洁元数据，不引入数据库快照或完整模型输入。
- [定性建议仍可能被用户理解为处方] → 使用 `advisory_only`、非预测措辞和显式可靠性说明；具体施用量继续引导到正式专业模型。
- [未来接入真实统计时实现者直接填值] → 集中式安全校验强制要求来源、方法、时间和范围完整。

## 迁移计划

1. 更新 OpenAPI 和前端类型，允许相关定量字段为 `null`，并支持 `degraded`、`result_kind`、`metric_meta`。
2. 更新县域诊断构造逻辑和集中式响应校验，移除全部固定定量值。
3. 更新结果整理接口，使其接受并传播安全的降级诊断。
4. 运行县域接口、核心引擎、摘要和 API 契约测试，并搜索活动代码中的旧周期和固定效果常量。
5. 发布后监控 `degraded/advisory_only` 响应比例和客户端解析错误。

回滚只能回滚接口部署，不得恢复旧占位数字。若客户端尚未完成适配，应临时隐藏对应定量 UI，而不是重新返回联调值。

## 开放问题

无。县域真实统计聚合和治理效果预测应分别通过后续 OpenSpec 变更设计。
