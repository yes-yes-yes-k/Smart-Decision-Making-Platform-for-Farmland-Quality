## ADDED Requirements

### Requirement: 县域诊断结构化接口
系统 MUST 支持围绕乐昌市县域问题发起结构化诊断请求，并输出结构化诊断结果，至少包括诊断主题、问题摘要、判定依据、重点区域提示和治理建议。

#### Scenario: 按主题发起县域酸化诊断
- **WHEN** 调用方以结构化参数请求县域酸化诊断
- **THEN** 系统 MUST 返回酸化主题下的问题摘要、诊断依据、重点片区提示和治理建议

#### Scenario: 按区域发起县域综合诊断
- **WHEN** 调用方请求县域耕地质量提升或限制因子识别诊断
- **THEN** 系统 MUST 返回与该主题对应的诊断摘要、建议查看的图层和治理方向

### Requirement: 诊断与地图联动
系统 MUST 将诊断结果与地图展示联动，确保每次诊断结果都能指向一个或多个建议展示的专题图层或区域范围。

#### Scenario: 根据诊断推荐图层
- **WHEN** 系统完成一次县域诊断
- **THEN** 系统 MUST 返回与该诊断相关的推荐图层或推荐查看区域，供前端直接切换展示

### Requirement: 缺失输入时允许模板回退
系统 MUST 在模型所需输入字段不完整时提供可解释的回退策略，优先使用位置最近邻或模板值完成计算，并在结果中说明回退字段与来源。

#### Scenario: 位置诊断缺少完整字段
- **WHEN** 调用方发起基于位置的诊断请求，且部分模型输入字段缺失
- **THEN** 系统 MUST 优先使用最近邻样点或模板值补齐计算，并在结果中标注回退来源与受影响字段

### Requirement: 诊断接口支持机器可读状态
系统 MUST 为诊断接口返回稳定的状态字段、错误信息字段和数据来源字段，避免未来 Agent 只能依赖自然语言判断调用结果。

#### Scenario: 诊断成功返回结构化状态
- **WHEN** 调用方成功完成一次县域诊断
- **THEN** 系统 MUST 返回可机读的成功状态、诊断主题、结果主体和来源说明

#### Scenario: 诊断失败返回结构化错误
- **WHEN** 调用方提交了无效参数或触发了诊断失败
- **THEN** 系统 MUST 返回可机读的失败状态、错误码或错误原因，并避免只返回笼统文本
