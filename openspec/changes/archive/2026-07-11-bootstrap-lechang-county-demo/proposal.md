## Why

当前阶段并没有可直接接入的模型 Agent，因此首要目标不是验证智能效果，而是把后续 Agent 需要调用的基础能力接口、数据契约和结果格式先建设出来。现有资料已经具备三类关键资产：乐昌市样例数据、空间分析与地图处理能力、土壤酸化模型与诊断链路，因此适合先收敛为“乐昌市县域基础能力接口版”，为后续 Agent 编排提供稳定底座。

## What Changes

- 新建一个面向乐昌市的县域基础能力范围定义，明确首版优先交付可供未来 Agent 调用的总览、诊断和报告三类接口能力。
- 定义基础能力所需的最小数据底座，包括行政边界、耕地范围、土壤点位和可直接映射到酸化/质量诊断的数据资产清单。
- 规划以非侵入式方式参考 `D:\work\AcidMap` 的空间图层处理能力，提取或重建当前仓库所需的地图图层、区域筛选、图层元数据和空间结果输出能力。
- 规划以非侵入式方式参考 `D:\work\suan\AcidificationModel\api` 的酸化建模、位置最近邻、诊断结果生成能力，在当前仓库内形成独立可运行的诊断能力。
- 定义结构化请求与响应契约，确保后续 Agent 可以稳定调用这些能力，而不是依赖当前阶段的自然语言交互或前端演示逻辑。
- 明确首版非目标：不做真实 Agent 编排、不做开放式智能问答、不做完整六大模型统一编排、不做生产级权限体系和在线训练。
- 明确非侵入式边界：不修改历史项目源码，不依赖历史项目服务在线运行，不将当前仓库实现回写到源项目中。

## Capabilities

### New Capabilities

- `county-quality-overview`: 提供乐昌市县域耕地质量总览基础接口，支持边界、耕地范围、土壤点位和核心指标图层信息的结构化输出。
- `county-smart-diagnosis`: 提供面向县域问题的结构化诊断接口，支持基于主题、区域或坐标触发诊断并输出重点片区和治理建议。
- `demo-report-export`: 提供面向汇报场景的结果整理接口，将诊断结果整理为可供前端或未来 Agent 继续加工的结构化摘要内容。
- `standalone-integration-runtime`: 提供非侵入式、可独立运行的集成运行时约束，确保当前仓库仅参考历史项目资产与实现思路，不修改源码且不依赖其在线运行。

### Modified Capabilities

- 无
