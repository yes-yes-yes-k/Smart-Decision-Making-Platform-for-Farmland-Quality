## Context

模型调用路由仅接收 `model_id`，并可透传 `area_code`、经纬度、`indicators` 与 `context`。成功时路由返回 `{ "status": "ok", "data": <核心引擎结果> }`；当前核心引擎仅注册 6 个专题模型。文档必须反映该实际契约，而不是将其他接口的字段作为顶层参数展示。

## Goals / Non-Goals

### Goals

- 在同一接口下提供可识别、可切换的 6 个请求示例。
- 用完整响应示例展示协同提升模型的依赖模型、分区建议、溯源和可靠性字段。
- 让 OpenAPI 源文件与 Apifox 接口文档保持一致。

### Non-Goals

- 不创建新的专题模型，不变更模型计算逻辑。
- 不将 OpenAPI 示例误当作 Apifox 原生接口用例或测试场景。
- 不为每一个模型复制一套完整的响应示例。

## Decisions

### 使用 OpenAPI 命名示例表达模型选择

在 `requestBody.content.application/json.examples` 中使用稳定的英文键，配合中文 `summary`。这使规范可被导出、导入和工具链读取，同时让文档页面能以模型名称展示示例。

### 以 6 个实际注册模型为唯一来源

示例与 `MODEL_SPECS` 和路由允许透传的字段保持一致。`model_id` 的枚举及示例不得包含未注册模型，也不得将未被路由透传的字段写在请求体顶层。

### 使用协同提升模型展示完整成功响应

协同模型包含依赖模型和分区建议，最能覆盖完整结果契约。文档保留一个该模型的完整 `200` 示例，另保留缺少 `model_id` 的 `400` 示例，避免文档冗余。

## Risks / Trade-offs

- OpenAPI 命名示例在不同 Apifox 视图中可能显示为接口文档示例，而非运行页的原生接口用例；批量执行需求应通过 Apifox 接口用例和测试场景单独配置。
- `indicators` 当前主要用于保持统一调用契约与生成回退信息，不应在文档中承诺其会改变 Demo 模型计算结果。
