## 为什么

当前县域诊断接口仍把为前端联调准备的固定 `period`、`improve`、`effect`、`cost` 和问题占比作为活动响应返回，用户可能将这些没有模型、监测或价格依据的占位值理解为真实治理预测。现在系统已经具备专业模型、数据溯源和机器可读降级状态，应收紧这一遗留接口的定量输出边界，避免 Demo 数据继续进入业务展示。

## 变更内容

- **BREAKING**：县域诊断不再返回固定的治理周期、提升率、治理效果、成本和问题占比；旧字段保留兼容键时其值必须为 `null`，不得继续填充联调占位数字。
- 对仍可保留的定性问题描述、治理方向和推荐图层增加明确的 `advisory_only`、来源和非预测性说明。
- 为每个可能出现的定量字段增加机器可读的可用性与依据元数据；只有同时具备真实数据来源、计算方法或模型版本、计算时间和适用范围时才允许返回非空数值。
- 当请求只能得到模板建议时，将诊断结果标记为降级或证据不足，避免以普通成功结果表达为真实诊断结论。
- 停止在 `measures`、`treatments`、`regions` 和 `base_data` 等兼容字段之间复制无依据定量值。
- 更新县域诊断 API 文档与示例，说明旧占位字段的迁移方式、`null` 语义、定性建议边界和真实定量结果的最低溯源要求。
- 增加回归测试，禁止固定周期、提升率、效果、成本和占比重新进入活动响应，并验证前端仍可读取稳定的主题、建议、图层及状态字段。

## 功能 (Capabilities)

### 新增功能

无。

### 修改功能

- `county-smart-diagnosis`: 收紧县域诊断的定量输出与模板回退要求，禁止把 Demo 占位数字作为真实或普通成功结果返回，并定义字段级可用性、依据和降级语义。
- `demo-report-export`: 诊断结果整理必须保留证据不足和定量不可用状态，不得在摘要、关键发现或建议中重新补造周期、提升率、效果、成本或占比。
- `api-documentation-examples`: 增加县域诊断安全响应示例与旧占位字段迁移说明，明确非空定量结果必须可追溯。

## 影响

- 主要代码：`src/ai_culti_demo/diagnosis.py`、县域诊断 API 路由及其调用适配层。
- API：`/api/v1/county/diagnose` 的旧定量字段将从固定值变为 `null` 或在有可靠依据时返回真实值；依赖旧数字直接渲染的前端需要适配不可用状态。
- 测试：县域接口、核心引擎、报告摘要和前端契约相关测试需要更新，并增加禁止占位定量值的负向断言。
- 文档：更新县域诊断请求/响应示例、字段语义、兼容说明和可靠性边界。
- 数据库与依赖：本变更不新增数据库表，不引入新的第三方依赖，也不实现治理见效时间或投资收益预测模型。
