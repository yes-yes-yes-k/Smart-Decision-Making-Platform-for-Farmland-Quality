## Context

model-7（FarmlandGradeObstacleAgent）通过 `FarmlandGradeRunner.run()` 调用 Fortran exe `Farmland_quality_evaluation.exe` 获取耕地质量等级评价结果。exe 调用本身工作正常（返回 status=ok），但 `parse_output` 函数无法正确解析 exe 的实际输出格式，导致 `parcel_info`、`indicators`、`composite_index`、`quality_grade`、`obstacle_degree` 全部为空。

**exe 实际输出格式**（通过运行 `A0001` 地块代码捕获）：

```
地块代码：A0001
经度：  112.973801
纬度：   25.324301
县区名称：武江区
二级农业区名称：闽南粤中农林水产区
------------------- 原始指标值 -------------------
酸碱度(SJD):    4.600
有机质含量(YJZ):   16.200
...
耕地质量综合指数：  0.6728
耕地质量等级：10等
------------ 障碍度因子（从大到小） ------------
质地构型    :  0.1690  中度障碍
地形部位    :  0.1516  中度障碍
...
```

**当前 parse_output 的解析逻辑问题**：

| 问题 | 当前逻辑 | 实际格式 |
|------|---------|---------|
| section 标记 | 查找 '地块信息' / '指标评价' / '综合评价' / '障碍度排序' | 实际是 '地块代码' / '原始指标值' / '耕地质量综合指数' / '障碍度因子' |
| parcel_info 分隔符 | 用英文 ':' 分隔 | 实际用中文 '：' |
| indicators 格式 | 期望空格分隔 4 部分 (name, raw_value, membership, weight) | 实际是 '指标名(代码): 值' |
| composite 提取 | section 标记不匹配，永远进不到 composite 分支 | '耕地质量综合指数：  0.6728' / '耕地质量等级：10等' |
| obstacle 格式 | 期望空格分隔 3 部分 (rank, indicator, degree) | 实际是 '指标名 : 障碍度值 障碍类型'，无显式 rank |

## Goals / Non-Goals

**Goals:**
- 让 `parse_output` 正确解析 exe 的实际输出格式
- 返回结构化的 `parcel_info`（地块代码、经纬度、县区、农业区）
- 返回结构化的 `indicators`（12 项指标的名称、代码、原始值）
- 返回 `composite_index`（综合指数数值）和 `quality_grade`（质量等级字符串）
- 返回结构化的 `obstacle_degree`（障碍度排序表：指标名、障碍度值、障碍类型）
- 保持 `run()` 方法的返回结构不变（向后兼容）

**Non-Goals:**
- 不修改 exe 调用逻辑（subprocess、编码处理、超时控制）
- 不修改 agent 注册和 API 接口
- 不解析潜力值表格（`| 评价指标 | 原数据 | 潜力值 | ... |` 部分），仅解析原评价结果
- 不修改 spec 级别的验收场景

## Decisions

### D1: section 标记识别改为匹配实际 exe 输出的关键词

**决策**：将 section 标记从 '地块信息'/'指标评价'/'综合评价'/'障碍度排序' 改为匹配实际输出的关键词：
- parcel section：识别 '地块代码：' 行（或 '经度：' / '纬度：' 等地块属性行）
- indicators section：识别 '原始指标值' 分隔线
- composite section：识别 '耕地质量综合指数' 或 '耕地质量等级' 行
- obstacle section：识别 '障碍度因子' 分隔线

**理由**：直接匹配 exe 实际输出的中文关键词，避免再次出现标记不匹配问题。

**替代方案**：用正则表达式匹配每种数据行，不依赖 section 标记。被否决，因为 section 标记方式更清晰、更易维护，且 exe 输出格式稳定。

### D2: parcel_info 用中文冒号 '：' 分隔，兼容英文冒号 ':'

**决策**：`parcel_info` 解析时优先用中文 '：' 分隔，回退到英文 ':'。

**理由**：exe 输出统一使用中文 '：'（如 '地块代码：A0001'），但兼容英文冒号可提高鲁棒性。

### D3: indicators 解析 '指标名(代码): 值' 格式

**决策**：indicators 解析格式改为匹配 '酸碱度(SJD):    4.600' 这种 '指标名(代码): 值' 格式，提取：
- `name`: 指标中文名（如 '酸碱度'）
- `code`: 指标代码（如 'SJD'）
- `raw_value`: 原始值（如 '4.600'，字符串保留，数值型可后续转换）

**理由**：exe 输出的指标行统一是 '中文名(英文代码): 值' 格式，用正则 `r'^(.+?)\((.+?)\)\s*[:：]\s*(.+)$'` 可稳定提取。

### D4: composite_index 提取数值，quality_grade 保留字符串

**决策**：
- `composite_index`：从 '耕地质量综合指数：  0.6728' 提取数值 `0.6728`（float 类型）
- `quality_grade`：从 '耕地质量等级：10等' 提取 '10等'（字符串保留 '等' 字后缀）

**理由**：综合指数是数值型，需 float 便于后续计算；质量等级是等级标识，保留字符串便于展示和比较。

### D5: obstacle_degree 解析 '指标名 : 障碍度值 障碍类型' 格式，rank 按顺序生成

**决策**：obstacle 解析格式改为匹配 '质地构型    :  0.1690  中度障碍' 这种 '指标名 : 障碍度值 障碍类型' 格式，提取：
- `rank`: 按出现顺序从 1 递增（exe 输出已是从大到小排序）
- `indicator`: 指标名（如 '质地构型'）
- `degree`: 障碍度值（float，如 0.1690）
- `level`: 障碍类型（如 '中度障碍'，新增字段）

**理由**：exe 输出已按障碍度从大到小排序，无需重新排序；障碍类型是有用信息（中度/轻度/无障碍），应保留。

### D6: 用正则表达式提高解析鲁棒性

**决策**：对 indicators、composite、obstacle 行使用正则表达式匹配，而非简单的 split。

**理由**：exe 输出中字段间有不定数量的空格，split 后空字段处理麻烦；正则可精确匹配并提取各组。

## Risks / Trade-offs

- **[风险] exe 输出格式未来变化** → 修复基于当前捕获的输出格式，如 exe 升级后格式变化，parse_output 可能需要再次调整。缓解：在 design.md 中记录完整输出格式样本，便于未来对比。
- **[风险] 指标名包含特殊字符** → 当前 12 项指标名均为中文，正则 `(.+?)` 可兼容。如未来出现含括号的指标名，需调整正则。
- **[权衡] 不解析潜力值表格** → 潜力值表格（`| 评价指标 | 原数据 | 潜力值 | ... |`）是改良后的预测结果，不属于本次 bug 修复范围（spec 要求的是"质量等级查询"和"障碍度诊断"）。如未来需要，可新增 `potential_indicators` 字段。
