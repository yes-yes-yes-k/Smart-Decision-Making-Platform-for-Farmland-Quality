# add-literature-ingestion-workflow Proposal

## Why

现有知识文档入口面向单文件上传：接口接收文件、基础分类和领域标签，按同一用户内的 SHA-256 查重后提交轻量线程池解析。该流程可以处理零散 PDF，但无法安全、可恢复地处理本次已盘点的千份级文献资料，也不足以支撑未来普通用户持续上传论文。

本批资料同时包含结构化论文清单、RIS、标准目录、扫描型 PDF、ZIP 中的 PDF/CAJ、补充政策与方法资料，并存在精确重复、文件名编码、失效索引、权威状态未核验等问题。若直接递归上传，会丢失 DOI、作者、标准号和来源等元数据，也无法对重复、OCR、CAJ 转换、失败重试和批次完成度进行治理。

本 change 建立统一的“文献接收—校验—管理员审核—转换—解析—索引”工作流，让管理员批量导入与用户单篇上传复用同一处理核心，同时保持现有上传客户端的 multipart 结构兼容。

## What Changes

- 新增清单驱动的管理员文献批次入库能力，支持 dry-run、幂等执行、断点续跑、逐项状态、失败重试和批次报告。
- 扩展现有 `POST /api/v1/docs/upload`，接收论文/标准相关元数据，返回稳定的异步处理状态和状态查询地址。
- 新增文档处理状态查询与可重试失败接口；失败原因不再只存在于日志中。
- 取消上传自动分类；用户必须选择至少一个有效领域标签，文档经管理员确认标签并审核通过后才进入入库处理。
- 所有审核通过的文献统一发布到公共知识库，包括普通用户上传的文献；审核前内容仅上传者和管理员可见。
- 普通上传不接受 ZIP 或服务器本地路径。
- 对上传内容执行扩展名、文件签名、大小、加密状态和处理器可用性校验；CAJ 在接收阶段预检转换能力。
- 将原始文件、派生 PDF、解析方式、OCR 质量、书目元数据和来源信息建立可追溯关联。
- 增加 CAJ 派生 PDF 保留配置，默认不长期保留派生 PDF，但始终保留原始 CAJ、转换哈希和转换溯源。
- 增加 SHA-256、DOI、标准号和规范化标题的分层去重；跨用户场景不得泄露其他用户文档信息。
- 对 PDF 实施逐页文本密度检测与分页 OCR，避免整本扫描件一次性渲染造成内存峰值。
- 将书目、标准、来源类别和解析质量等元数据同步到文档记录及向量 chunk。
- 保留来源资料的九类专题和交叉主题，同时要求显式映射到系统现有领域标签；不得从文件夹名称静默授予领域权限。
- 对标准、政策、征求意见稿等资料记录权威状态；未核验资料默认只作为参考来源。
- 更新上传、状态查询、重试、重复、CAJ 依赖不可用和元数据校验的 API 文档示例。

## Capabilities

### New Capabilities

- `literature-ingestion-batches`: 管理员清单驱动的批量文献预检、执行、恢复、报告及档案安全展开能力。

### Modified Capabilities

- `file-upload-management`: 扩展用户文献上传契约、内容验证、处理阶段、错误持久化、重试和 CAJ/PDF 处理行为。
- `database-models`: 增加文献元数据、解析溯源、批次和逐项任务数据模型。
- `vector-store`: 将文献标识、来源、文档类型、权威状态和解析质量传播到 chunk 元数据。
- `api-documentation-examples`: 增加用户论文上传和管理员批次入库相关请求、响应及错误示例。

## Initial Corpus Context

首次应用该工作流的资料盘点基线为：954 个目录内 PDF、ZIP 内 121 个 PDF 和 86 个 CAJ。目录内发现 3 个精确重复副本；ZIP 内 207 份文档彼此及与目录内 PDF 均无字节级重复。扣除已知精确重复后，最多 1158 份唯一候选文档仍需进一步按 DOI、标准号和规范化标题去重。

该外部资料目录只作为首次迁移输入，不得成为应用运行时依赖，也不得把其绝对路径写入业务代码或数据库迁移默认值。

## Non-Goals

- 本 change 不执行本批论文的正式入库。
- 本 change 不修改检索排序、问答提示词或知识图谱构建策略。
- 本 change 不自动认定标准现行有效或版权许可；“审核通过的文献统一公开”是本系统的既定产品策略，不由入库程序逐篇推断。
- 本 change 不从互联网自动补齐缺失全文或书目数据。
- 本 change 不建设完整前端页面；仅定义后端契约和前端所需状态。
- 本 change 不把 ZIP 开放为普通用户上传格式。
- 本 change 不强制扩展现有三个一级领域；来源九类专题先作为独立元数据保留，并通过显式配置映射。

## Impact

- API：扩展 `POST /api/v1/docs/upload`；新增文档处理状态、重试以及管理员批次查询/控制接口。
- 数据库：扩展 `kb_document`，新增 `kb_ingestion_batch` 与 `kb_ingestion_item`。
- 入库服务：抽取统一 ingestion service，供单文件上传和批次任务复用。
- 文件处理：增加安全档案展开、CAJ 转换预检、分页 OCR 和派生文件管理。
- 权限：上传者可查看自己的待审核提交，管理员负责标签确认与批准/驳回；批准并完成索引的文献统一为公共可检索，批次入口仅管理员或离线运维命令可用。
- 运维：需要 Poppler、Tesseract 中文语言包及 CAJ 转换器的可用性探测与健康检查。
- 兼容性：旧客户端仍可省略新增书目字段并按 `document_kind=other` 处理，但必须提交有效 `domain_labels`；文献不再支持自动分类或私有发布语义。
