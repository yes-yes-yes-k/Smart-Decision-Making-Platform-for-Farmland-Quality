## Context

用户已通过九项设计选择确认方向并授权从M0实施。运行事实见`artifacts/knowledge_platform/recovery-m0-v1/inventory-v2.json`、`processes-v1.json`及`runtime-config-v1.json`；边界见`docs/adr/0001-separate-candidate-recall-from-published-claims.md`与`0002-source-retrieval-before-graph-dependent-comparison.md`。

## Goals / Non-Goals

首期交付有原文依据、能保留条件差异的文献证据对照。文献容量、任务抽取覆盖、已发布断言量分别报告；首期新增研究断言始终待审。规模工程与语义质量独立推进，保留必要风险回归，不另起评测数据建设主线。

不在M0修改业务数据、初始化完整应用、安装扩展、启动服务或调用模型。后续模型测量先核实预算归属和硬上限，不挪用外部评测账本。

## Decisions

### 原文检索与图谱辅助

现有全文/向量来源检索应独立可用。图召回走可追溯的适配边界，记录所用图及版本、不可用状态与贡献；不能以一次来源回退宣称GraphRAG增益。先测量现有BM25/JSON路径，再按瓶颈改造，不预先绑定新搜索产品。

### 研究记录与既有Claim

现有Claim字段和候选生命周期可复用，但自由statement/payload不能自动视为条件比较契约。M1实现前冻结最小记录契约与版本，区分文献/研究记录身份、措施、指标、结果、条件及各字段的来源；同一文献多个试验记录不静默合并。未知、否定及不确定性有明确表达，数值与单位保留原义，不自动合并相反结果或做效应汇总。

### 候选读取与发布隔离

仅允许当前授权、合格、版本有效的来源候选参与内部召回。候选输出保留待审身份，引用可回原文；不复用发布API绕过审核。拒绝或失效的候选不得作为有效线索。对照是来源绑定的派生结果，不增加已发布断言量。

### 异步与结果有效性

检索同步返回；对照单独发起并有明确的排队、运行、完成、失败、取消和来源失效状态。并发、超时、重试与调用预算均有界，不以部分失败产生虚假完整表。复用身份至少覆盖请求条件、来源内容版本、记录/生成版本、相关候选状态和权限范围；读取时重验可见性与来源有效性。

### 迁移与部署前置

本机当前没有KG表、可用AGE扩展或运行的API/worker。不能为完成M0启动完整应用：`create_app`会执行自动补表/迁移并初始化检索依赖。M1需提供明确、可回滚的数据结构与隔离验证方案，不能靠启动应用隐式变更当前库，也不要求先部署AGE才能开展原文对照。

## Risks / Trade-offs

- 未审核线索可误召回：保留状态，每项回答仍由原文支持，不提升信任等级。
- 条件未记录可能造成错误比较：未知显式展示，不当作任意条件匹配。
- 跨库并发变化：M0仅各库只读快照，不能证明原子一致；产品读取需做来源版本重验。
- 索引与模型成本未知：先测量，再冻结下一阶段容量/SLO及模型批次，不给未实测的日期或成本保证。

## Migration Plan

M0盘点与规范 → M1十篇候选检索/对照/失效闭环 → M2现有语料增量运行 → M3隔离10k/100k容量。保留旧已审图与既有API兼容读路径；不迁移或改写历史评测。M1不自动发布断言，因此不勾选原平台AGE发布试点。

## Open Questions

依赖M0/M1实测后确定的数值：查询及对照延迟、每篇成本、可用并发、积压与容量阈值。依赖后续具体迁移设计的内容：研究记录存储结构、异步任务及缓存实现。未确定项不能通过猜测视为已验收，也不要求用户选择常规库或工具。

## M2 implementation evidence

当前语料全量112168块已在隔离Chroma/HNSW克隆验证。关键词索引改为SQLite FTS5持久化派生库，首次按500块流式建立，正常重启无正文读取；更新预写范围恢复日志，失败保留pending，重启事务恢复。按原文哈希判断是否需重新分词；查询只分词查询并核验有限候选的当前内容/权限。新证据检索面向当前1144份合格来源，按候选两轮批量PG查询及原件SHA256校验；十篇研究记录/对照范围不随检索范围扩大。排序公式变化需另行检查业务质量，不宣称旧排序等价。

比较任务默认每用户20、全局100个queued/running，满队列429；SQLite写保留和PG事务advisory lock串行准入，复用请求先查已存在身份。超时/租约/重试和待审信任边界保持。PG准入锁未做真实多进程压测，当前队列测量为隔离SQLite。完整结果及限制见`docs/knowledge-engineering-m2-results.md`；M3数值建议尚未冻结，不能据M2的零模型、非部署测量宣称100k或语义质量通过。

## 当前R阶段设计补充（2026-10-30）

M1/M2完成后优先执行[细化任务](../../../docs/knowledge-engineering-retrieval-quality-tasks-v1.md)，M3延后。领域边界遵循ADR-0003，Python/PostgreSQL优先路线遵循ADR-0004。现有研究记录与KG候选不是同一条已经贯通的链路；须补齐真实来源到持久实体/关系、Claim及证据关联的写入和重启后读取，候选读取与发布隔离。

检索对照分为强词法/向量混合、同领域过滤、增加图关联三个配置，分别归因过滤和图路径收益。运行入口需显式迁移，隔离验证后启用本机后端；不修改前端。新增调用按具体请求和独立账本准备预算，历史额度不自动转用。此前Open Questions中的结构/队列内容须先核对M1/M2已有实现，仅处理剩余缺口，不重复开发。
