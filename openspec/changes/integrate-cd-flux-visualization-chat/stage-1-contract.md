# 第 1 阶段：冻结的数据与单位契约

日期：2026-11-10。这是阶段 2 的实现输入，DDL 尚未执行。

## 单位与独立推导

证据：`framework/models/cd_flux.py` 标注初始储量 g/ha、七分项 g/ha/a、0–20cm 容重；`cd_flux.py` 的旧公式为 `(initial+net)/(2000*bd)`。现有代码没有容重单位的原始数据字典证据，因此不能宣称旧数据容重已核验。

面积及质量换算参照 [NIST 面积单位](https://www.nist.gov/pml/owm/metric-si/si-units-area) 和 [NIST 质量单位](https://www.nist.gov/pml/owm/si-units-mass)。以下为量纲推导，非污染迁移过程验证。

固定定义：容重 rho 为 g/cm³（等值 Mg/m³），厚度 d 为 m，年度跨度 dt=1 a。每公顷土壤质量 `M=10000*d*1000*rho kg/ha`；净增储量为 `Net*dt g/ha`；末期浓度 `C1=1000*(S0+Net*dt)/M mg/kg`。d=0.2 时恰为 `(S0+Net)/(2000*rho)`。因此旧公式在这些假设下数值一致；常量 `SOIL_MASS_KG_HA=2000` 的名称不能解释为实际土壤质量，实际质量为 `2000000*rho kg/ha`。

独立复算：rho=1.3，d=0.2，S0=600 g/ha；沉降/灌溉/农化/企业分别10/5/3/2，渗漏/径流/籽粒/秸秆分别1/2/3/4，全部 g/ha/a。In=20、Out=10、Net=10；土壤质量2600000 kg/ha；末期610000/2600000=0.2346153846 mg/kg。若给初始浓度0.3 mg/kg，其储量是780 g/ha，不能将0.3直接填S0；相同净输入下末期为0.3038461538 mg/kg。

条件：完整八项、所有非负分项、有限数、rho>0、d>0、明确一年跨度；S0与初始浓度只选其一，或验证二者一致。企业未知只返回七项小计，不给完整净通量/浓度。净输出导致负储量时返回不适用错误，不截成正常零浓度。

版本 `cd_flux_mass_balance_v2` 使用上述显式单位。容重、厚度的默认仅在有依据并经用户接受后采用；无原始单位依据的业务记录不标为已核验。legacy 七项公式保留 `legacy_v1`，不改写原值。此阶段只验证算术与条件，真实样品适用性需后续数据验收。

## 数据结构与兼容策略

采用并行 v2 表而非原表原地替换：保留原始表以支持旧客户端与安全回滚，新版年度/来源/企业语义进入 `cd_flux_input_v2/cd_flux_output_v2`。迁移脚本在阶段 2 实现，先备份、检查行数与冲突，再复制 legacy 行。来源必须从可追溯映射或导入依据确认，无法确认时记 unknown，不能硬填 native。

输入固定列见 `stage-1-schema.sql`；所有数值输入的依据、原始单位、默认接受、导入批次记录在 provenance。年度允许 NULL，仅用于显式 legacy 模式。未知年度采用 PostgreSQL 17 支持的 NULLS NOT DISTINCT 唯一约束。新 CSV 必含来源、年度及企业字段，企业空值为未知；legacy CSV 则年度/企业未知。两种模式均先验证整批，非法行拒绝整批。沿用旧接口时应明确 legacy 模式与响应标记。

输出包含公式版本、所用输入 revision、八项覆盖和单位状态；默认查询只返回 input_revision 等于当前输入 revision 的结果，旧输出可按历史显式查询。输入同键变更 revision 递增。重复同修订同公式计算幂等。独立对话试算不写这两表，沿用 CdTrial 并加 payload schema_version/type。

来源、年度、公式版本在比较/统计/CSV/地图中保持一致。对 unknown 来源单列，不能混入 native/ported。企业“明确0”和“未知”必须分别可追溯。

回滚只关闭 v2 路由并恢复旧业务入口，v2表及新年度数据保留；没有完成导出和冲突检查不得 drop v2 或压平年度键。

## 阶段 2 前置结论

可以按 v2 契约开发迁移与纯计算。旧记录浓度的可信单位、真实年度、企业输入并未因本推导获得补齐；缺少这些依据时按未知处理并限制输出。绘图依赖缺失和 flux 表未迁移纳入环境准备，不能视作业务能力已就绪。
